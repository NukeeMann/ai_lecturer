- `klasyfikacja-pojazdow-mstar-onnx-inference` cites "trzeciego stopnia ATR z poprzedniej lekcji (4.5)", but the three-stage ATR exposition (and the `clutter_truth` MSTAR forward-pointer) is in `detekcja-pojazdow-na-ladzie` — which actually IS 4.5, so the reference is correct numerically yet inconsistent with the same lesson's other slip (`previous lesson 4.5` appearing inside that same 4.5). ## Redundancy

- The multiplicative-speckle model $I = R \cdot N$ with $\mathbb{E}[N]=1$, $\operatorname{Var}[N]=1/L$ is fully derived three times: first in `speckle-dlaczego-to-nie-jest-szum-gaussowski` (1.4), then re-derived from scratch in `dlaczego-klasyczne-filtry-padaja-na-sar` (2.2) ("Kluczowa zmiana matematyczna w jednej linii… trzy konsekwencje, każda zabójcza dla klasyki"), then re-stated in `non-local-means-i-nowoczesne-despeckling` (2.4). 2.2 does say "te same trzy filtry, co poprzednio", but the speckle-model derivation block underneath duplicates 1.4 rather than recapping it. Pick 1.4 as canonical and have 2.2 / 2.4 cite it in 1–2 lines.

- `gauss-median-bilateral-na-optyce` (2.1) and `dlaczego-klasyczne-filtry-padaja-na-sar` (2.2) re-derive bilateral as "Gauss × intensity weight" and the median's robustness-to-impulses argument twice in close succession. 2.2 acknowledges 2.1 in its opening sentence, so the redundancy is softened, but the failure-mode table for Gauss/median/bilateral in 2.2 effectively re-runs the same comparison as 2.1's table with one row added (multiplicative noise). Trimming 2.2 to "Gauss, median and bilateral as recapped in 2.1 — here is what changes under $I = R\cdot N$" would tighten the module.

- The CA-CFAR algorithm (training/guard window plus `α = gammaincinv(L, 1−Pfa)/L`) is derived in `thresholding-otsu-vs-cfar` (4.1) and then re-explained — not just re-coded — in `cfar-detekcja-statkow-na-morzu` (4.4), `detekcja-pojazdow-na-ladzie` (4.5), and `pipeline-sar-cfar-morfologia-klasyfikator` (6.3). Each downstream lesson cites the prior, but 4.4 in particular reintroduces the formula box `T = α·μ_bg` as if for the first time. Replacing the formula box in 4.4 with "(recall 4.1's $T = \alpha \cdot \mu_\text{bg}$)" plus a one-liner on `α(Pfa=1e-4, L=4) ≈ 3.98` for this scene would be enough.

- The `cfar-edge-i-detektor-touziego` (3.2) "Od strength do binarnej decyzji" section explains empirical CFAR (homogeneous-region percentile → threshold) and `thresholding-otsu-vs-cfar` (4.1) explains analytical CFAR (Gamma quantile via `gammaincinv`). The two are presented as separate inventions without one citing the other, even though both name "CFAR" and quote the same $P_\text{fa}$ contract. A single bridging sentence in 4.1 — "the empirical variant you saw in 3.2 estimates `t` from the lower CV percentile; here we close the loop with the analytic Gamma quantile" — would prevent the second-time reader from feeling they have re-learned CFAR.

## Notation Consistency

- Sentinel-1 C-band wavelength λ is quoted with four different precisions: `~5,6 cm` (`optyka-vs-sar-dwa-rozne-swiaty`, `jak-powstaje-obraz-sar-apertura-syntetyczna-w-intuicji`), `~5,5 cm` (`amplituda-i-faza-dane-zespolone-ktorych-nie-ma-w-optyce`, `polarymetria-hhhvvvvh-zamiast-rgb`), `5,547 cm` (`faza-interferometryczna-pomiar-deformacji`), and `0.0556 m` (the matplotlib code in `jak-powstaje-…`). All are the same constant rounded differently; the InSAR lesson uses 5,547 cm to derive λ/2 = 2,77 cm per fringe, so a learner who carried 5,5 cm forward will reproduce 2,75 cm and disagree by 1%. Pick one canonical value (5,547 cm) and round elsewhere.

- Sigma-nought notation drifts between `$\sigma^0$` (canonical in `formaty-danych-sar-grd-slc-kalibracja`, `cfar-detekcja-statkow-na-morzu`, `pipeline-sar-cfar-morfologia-klasyfikator`, `synteza-…`) and `$\sigma_{0,1}^{dB}$`/`$\sigma_{0,2}^{dB}$` (subscript-zero with date index) in `change-detection-optyka-vs-sar` only. The change-detection lesson is the lone outlier; align with `$\sigma^0_1$`, `$\sigma^0_2$`.

- The phasor / phase symbol is `$\varphi$` in `amplituda-i-faza-dane-zespolone-ktorych-nie-ma-w-optyce` and in `faza-interferometryczna-pomiar-deformacji`, but reduces to `$\phi$` (plain phi) inside the same `faza-interferometryczna-…` plot captions and to `arg(z)`/`np.angle` in code. The plain `\phi` and `\varphi` appearing in the same lesson is the conflict; pick `\varphi` everywhere in math and let code keep `phi`.

- The bandwidth/window parameter `h` is overloaded: it is satellite altitude `h ≈ 693 km` in `jak-powstaje-obraz-sar-apertura-syntetyczna-w-intuicji` and `geometria-sar-foreshortening-layover-shadow`, but bandwidth of the NL-means similarity kernel in `non-local-means-i-nowoczesne-despeckling` (`h ∈ [0.04, 0.15]`), and component bounding-box height in `pipeline-sar-cfar-morfologia-klasyfikator` (`h = int(ys.max() − ys.min() + 1)`). Each usage is locally clear, but a learner browsing across lessons will collide. Consider renaming the NL-means scalar to `h_nlm` or `bandwidth` in narrative, and the bbox height to `H_box`/`bbox_h`.

- `L` is used both for the number of looks (`L ≈ 4` everywhere in modules 1–5) and for radiance / luma (`L = 0.299 R + 0.587 G + 0.114 B` in `pipeline-optyczny-detekcja-statkow`). The optical-pipeline lesson explicitly defines luma as `L` once and then drops back to "luma" in code (`luma = …`), but the formula line conflicts head-on with `L` as ENL elsewhere. Rename the optical formula's left-hand side to `Y` (the ITU-R BT.601 convention) or to `luma`.

- Window size convention: `win` in CA-CFAR (`thresholding-otsu-vs-cfar`, `cfar-detekcja-statkow-na-morzu`, `detekcja-pojazdow-na-ladzie`, `pipeline-sar-…`) is the **half-side** (full side `= 2*win + 1`), but `window=9` in `watershed-mean-shift-k-means-na-obu-modalnosciach` is the **full side**. Both lessons pass an int called `win`/`window` into `uniform_filter` but with opposite semantics. Either rename one (e.g. `half_win` vs `window`) or document the convention up-front in 4.1 and reuse the same name with the same meaning thereafter.

- Compactness is written `c` in `pipeline-sar-cfar-morfologia-klasyfikator` and `cp` in the same lesson's classifier-rule box ("`A·cp·SNR`") and figure caption. Pick `c` or `cp` and use it in the formula, the diagram label, and the test docstring.
