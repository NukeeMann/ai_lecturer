Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.

Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.

- **Learnings for future iterations:**
  - **pdfjs-dist + Next.js dev = broken without `serverExternalPackages`.** pdfjs-dist uses a runtime `import('./pdf.worker.mjs')` (with a `webpackIgnore: true` magic comment that vite/turbopack do NOT honour) to set up its fake worker. Turbopack rewrites that path against the bundled chunks dir and the lookup fails: `Setting up fake worker failed: "Cannot find module '.../.next/dev/server/chunks/pdf.worker.mjs'"`. The standalone tsx-driven smoke test in US-127 ran outside Next.js, so this never surfaced there. Fix is one line in `next.config.ts`: `serverExternalPackages: ["pdf-parse", "pdfjs-dist"]`. Generalises to *any* dynamic-`import`-using server-only npm dep that bundles its own assets — when in doubt, externalise.
  - **PDFs commonly carry U+0000 in extracted text.** pdf-parse forwards them straight through. POSIX argv cannot carry null bytes, and Node's `child_process.spawn(cmd, [...args])` enforces that — so the `\x00`-bearing markdown blew up the subprocess Claude connector with `The argument 'args[1]' must be a string without null bytes`. Strip them at the EARLIEST point (the extractor) so every downstream consumer of the sibling .md is safe — not just the wizard prompt path. One-liner: `p.text.replace(/ /g, '')`.
  - **The wizard prompt builders' "extracted from <fmt>" heading must be derived, not hardcoded.** US-124 had only docx, so the literal `(extracted from docx)` was harmless. As soon as US-127 added pdfs, it became misleading: a .pdf source got labelled as docx. Any future format (.pptx → US-?) inherits the right behaviour for free now: `path.extname(s.extractedFrom).slice(1).toLowerCase()` does the work. If `extractedFrom` ever has no extension (shouldn't happen, but defensive), the suffix falls back to `binary`.
  - **`GENERATION_DEBUG=1` env var → tmpdir() prompt dump** is a clean smoke-test mechanism that doesn't require mocking the connector or modifying the test build. The route still hits the real connector — only the captured prompt is side-effected onto disk for offline assertion. Cheap, opt-in, keeps the production path unchanged. Useful for any "what did we send to the model?" debugging in the future.
  - **Context-window budget math for Polish:** ~150k chars ≈ 55-60k tokens (Polish runs at ~2.5 chars/token, lower than English's 3.5-4 because of accented characters and richer morphology). With 200k Opus context, a 150k char inline budget leaves ~140k tokens for the rest of the prompt + the model's reply. The 60k per-file cap means a single long upload can use ~40% of the budget alone, which is the realistic "one big textbook PDF" case. If we ever go to multi-textbook uploads (>2 large PDFs) we'll need either the adaptive head/tail truncation or the multimodal-image path the AC explicitly defers.
  - **Restarting the Next.js dev server in this WSL setup needs `kill <next-dev-pid>`, NOT killing the npm-run wrapper.** `next dev` becomes its own process group child of the npm wrapper, and signalling the wrapper alone leaves the listener on port 3000 (a "next-server" child) holding the port. Always `kill` the actual `next dev` PID — `ps -p <wrapper-pid> -o pid,ppid,cmd` then walk the tree.
