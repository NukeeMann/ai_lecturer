## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.

- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.

  - The home `page.tsx` already had a `CourseCardWithMove` wrapper exposing a `MoreHorizontal` button at the same `top: 12, right: 12` slot the AC asks the new `MoreVertical` menu to occupy. Don't try to merge them — keep both buttons by introducing `CourseCardWithMenu` as a NEW wrapper at right: 12, and shift the move button to right: 48. Two 28×28 icons + 8px gap fit comfortably inside the card padding (`var(--space-5)`). This also keeps the AC test ID (`course-menu-btn-<slug>`) unambiguous: the move button's existing test ID (`course-card-move-<slug>`) is unchanged so US-127's tests still pass.
  - The DropdownMenu / AlertDialog spec calls for shadcn primitives, but this codebase has no `@radix-ui/*` packages installed and the `src/components/ui/` dir is empty (only a `.gitkeep`). Don't pull radix in for one menu — the existing `AvatarMenu.tsx` / `CourseCardWithMove` pattern (custom popover wired to outside-click + Escape via the page-level `[data-popover-host]` listener) is already the established convention. Same for the AlertDialog: the page-level custom modal with `role="alertdialog"` + `aria-modal` + Escape + backdrop-click-to-close is sufficient and matches what `window.confirm`-replacements already do elsewhere (e.g. ResumeBanner's confirm in /create).
  - The `Request.json()` API will throw on an empty body (`SyntaxError: Unexpected end of JSON input`). For an "optional body" DELETE handler, gate on `content-type` + try/catch around `req.json()` and treat any failure as "no body, use defaults". Don't blindly `await req.json()` — fetch's no-body DELETE (which the AC's "404 refetch" path triggers from playwright via `Response.delete` style requests) would otherwise blow up before the 404 check.
  - For "active-run check on the slug to be deleted", `getActiveRunSummary()` is the right primitive (NOT `getActiveRun()` alone): the cold-start fallback inside `computeActiveRunSummary` already surfaces a `.generating.json`-only run after a server restart, which is exactly when the user might try to nuke the half-finished course. The /generation-state route's pattern of using `getActiveRun()` only checks the in-memory run — that misses the cold-start case.
  - `fs.rename` across devices throws EXDEV (e.g. /courses/ on a tmpfs mount, /home/ on the OS disk). The fallback is a recursive copy via a hand-rolled `copyDirRecursive` (Node's `fs.cp` is async-only and ships with caveats around symlinks; rolling our own keeps symlink semantics explicit) followed by `fs.rm(src, { recursive: true, force: true })`. Tests on tmpfs hit this path; production on a single device never will, but the code is small enough not to gate behind a feature flag.
  - The dialog title quote characters: React's JSX `&ldquo;`/`&rdquo;` render as the curly Unicode quotes (U+201C/U+201D), not the ASCII `"`. Playwright assertions on the title text need to match either form — the test uses `/[“"]/.test(...)` regex to be tolerant. Worth noting because the AC literally writes `Delete "<course title>"?` with ASCII quotes, but the rendered page uses curly ones for typographic correctness.
  - For the `DELETE` body parsing, also accept `{}` or omitted `mode` and treat as soft. Only reject (400) when `mode` is present AND not `'soft'`/`'hard'`. This matches "optional body" semantics and avoids a spurious 400 when the client sends no Content-Type at all.
  - The `Course` schema (`src/lib/schemas/course.ts`) requires `accentColor` to be in the small enum `default|indigo|emerald|terracotta|black` and `icon` to be a string. The home explorer's `AccentIcon` falls back to `BookOpen` if the icon name isn't in lucide's `iconNames` set, so seeding a course with `icon: "function-square"` (which IS in lucide-react/dynamic) gives a distinct visual; falls back gracefully if a future lucide upgrade renames it.
  - When seeding test courses for browser verification, set BOTH `COURSES_ROOT_OVERRIDE` and `PROGRESS_FILE_OVERRIDE` on the dev server so the soft-delete progress wipe doesn't touch the user's real `~/.ai-lecturer/progress.json`. Same pattern US-140 used for its `/tmp/ai-lecturer-test-courses/` seeded run.
  - The home GET `/api/courses` listing iterates every `entries` in `coursesRoot()` — a `.trash/` subdir without a `course.json` would be silently skipped via the `ENOENT` continue, but the deeper `.trash/<slug>-<stamp>/course.json` IS visible to the readdir of `coursesRoot()` only as `.trash` (a single dir entry). Adding the `entry.name.startsWith('.')` filter is still wise because (a) the warn log on `course.json` ENOENT inside `.trash/` would clutter logs, and (b) future `.trash/` siblings (a `metadata.json` index, a `restore-log.json`) would otherwise be at risk of being misinterpreted.

- **Learnings for future iterations:**
  - The PRD says "reuse the existing spawnClaude helper from src/lib/server/generation.ts" but no such standalone export exists — `generation.ts` only consumes Node's `defaultSpawn` directly through its `SpawnDeps.spawn` injection point. So this story extracts a fresh small helper module (`src/lib/server/extend.ts`) that owns its own spawn dep with a `__setExtendSpawnForTesting` hook. Same dependency-injection pattern (`__set...DepsForTesting`) as `generation.ts`'s `__setSpawnDepsForTesting` — keep that test-hook naming for future agent-spawning routes.
  - `CourseSchema` in `src/lib/schemas/course.ts` does NOT carry per-lesson `description` (only `slug`, `title`, `estimatedMinutes`). The actual descriptions live in each `LessonSchema` JSON under `/courses/<slug>/lessons/<lesson-slug>.json`. So an "extend"-style endpoint that needs to feed lesson context into an agent has to enumerate `course.modules.flatMap(m => m.lessons)` and read each lesson JSON to pull out the `description` field. That's what `readLessonDescriptions` does, and it falls back to `''` when a lesson file is missing/invalid (don't 500 on partially-generated courses where some lesson files haven't been written yet — the agent handles missing context fine).
  - `Request.json()` throws on an empty/non-JSON body. For POST handlers that REQUIRE a JSON body, just wrap the call in a try/catch and return 400 directly — the existing PUT routes (`route.ts:54-58` for course PUT, `[lessonSlug]/route.ts:62-65` for lesson PUT) already do this; mirror that pattern instead of inventing a new validator.
  - For tests that need to mock a spawned child process driven by stdin, `EventEmitter` + `Writable` + `Readable` pairs work cleanly: the `Writable.final` callback fires when the route calls `child.stdin.end()`, which is the point at which it's safe to push stdout content + emit `exit` and `close`. Defer those events one tick via `setImmediate` so the route's `stdin.end(...)` callback resolves before the test sees the close — otherwise the close listener races the data drain and tests intermittently see empty stdout.
  - To force the cold-start active-run scan in `getActiveRunSummary` to surface as `active: true` for a specific slug, write a `.generating.json` marker at `/courses/<slug>/.generating.json` with `childPid: process.pid` + `slug` + `stage`. The scan calls `process.kill(pid, 0)` to liveness-check; `process.pid` is alive by definition. This is the right pattern for unit-testing 409 busy responses without spinning up a real child — `__resetGenerationForTesting()` afterwards still cleans up the in-memory bookkeeping, and the marker file is removed when `coursesRoot` is rm'd in `afterEach`.
  - Skill `.md` filename matters: per the AC, this skill lives at `scripts/ralph/skills/extend_course/extend_course.md` (note: lowercase, NOT `SKILL.md` — the existing `init_course/SKILL.md` and `generate_lesson/SKILL.md` use uppercase `SKILL.md`, but the AC for US-143 explicitly writes the lowercase form so I followed it). claude's `-p` mode finds the skill via the prompt referencing the explicit path, so the case difference is harmless — but if a future story wants to consolidate to a uniform convention, this is a place where they diverge.
