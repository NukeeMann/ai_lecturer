## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.

- **`PythonError` shape (Pyodide 0.26).** A Pyodide exception thrown out of `runPythonAsync` is a `PythonError` (`err.constructor.name === 'PythonError'`, `err instanceof Error === true`). The headline `<Type>: <msg>` is the LAST non-empty line of `err.message`. - **Learnings for future iterations:**
  - `unzipper@0.12.x` requires `serverExternalPackages` treatment in Next 16. Turbopack statically scans every `require()` in the bundled file graph, including the optional `require('@aws-sdk/client-s3')` inside `unzipper/lib/Open/index.js` (the `Open.s3_v3` helper). Without `serverExternalPackages: ['unzipper']`, the route's import path breaks at compile time with "Module not found: Can't resolve '@aws-sdk/client-s3'", even though we never touch S3. Same fix pattern as `pdf-parse` / `pdfjs-dist` already shipped.
  - Detect ZIP symlinks via `(externalFileAttributes >>> 16) & 0o170000 === 0o120000`. archiver does NOT expose a clean public API to write a symlink entry directly (it dereferences `fs.lstat` symlinks); for tests, hand-craft a normal ZIP and patch the central-directory record in place: locate signature `0x02014b50`, set version-made-by upper byte to `0x03` (Unix) at offset+4, and write `(unixMode * 0x10000) >>> 0` to offset+38 (the `>>> 0` is required because `0o120755 << 16` overflows JS's signed-int bitwise ops and `Buffer.writeUInt32LE` rejects the negative result).
  - `unzipper.Open.file(zipPath)` reads only the central directory (cheap), then each `file.stream()` lazily decompresses the entry. Pair with `pipe(createWriteStream(target))` for memory-bounded extraction. The CD walk is also where to enforce all "no `..`" / "single top-level" / total-uncompressed-cap invariants — bailing there means we never extract a malicious entry to disk.
  - Two-tier ZIP-slip defense: (a) reject any entry path containing a `..`, `.`, leading `/`, `\`, or NUL during the CD inspection; (b) for every entry actually extracted, recompute `path.relative(extractRoot, path.resolve(extractRoot, entry.path))` and reject anything that starts with `..` or is absolute. Either tier alone catches the obvious cases; together they also catch normalisation tricks (e.g. `foo/bar/../../etc`).
  - For routes that accept binary multipart bodies, the test harness can lean on the global `Blob` + `File` Web constructors. Buffer → Uint8Array conversion is required under TS `strict` mode: `const view = new Uint8Array(new ArrayBuffer(buf.byteLength)); view.set(buf); new Blob([view], {type:'application/zip'})`. Skipping the intermediate `Uint8Array` triggers a "Buffer<ArrayBufferLike> not assignable to BlobPart" error because Node's Buffer carries an `ArrayBufferLike` (which can include `SharedArrayBuffer`) and Web `Blob` insists on plain `ArrayBuffer`.
  - Next 16 dev rejects requests over `127.0.0.1` host with the `allowedDevOrigins` warning (silent payload-load failure → React tree never hydrates → page stays at "Loading…"). Always target `localhost:<port>` from playwright tests against the local dev server. The skill's `detectDevServers` helper still emits 127.0.0.1; override with `TARGET_URL = 'http://localhost:<port>'` at the top of the test script.
  - The `ImportCourseCard` parent (`DashboardPage`) already owns the `loadData` + `showToast` callbacks. Wiring the import is just `onImported={loadData} showToast={showToast}` — no new state needs to live in the parent. The card maintains its own `hover/dragOver/loading` local state, so adding it doesn't fan out across the existing search/grouped/empty branches.

- **Learnings for future iterations:**
  - **Next 16 / Turbopack rejects static `import { renderToStaticMarkup } from 'react-dom/server'` from any module reachable from an App Router route handler**, even though route handlers ARE server-side. The error reads "You're importing a component that imports react-dom/server. To fix it, render or return the content directly as a Server Component instead". The clean workaround is `createRequire(import.meta.url)` + lazy `nodeRequire('react-dom/server')` inside the renderer — this defers resolution past Turbopack's static-import analysis. Same trick applies to any third-party renderer Turbopack flags.
  - **Lucide-react icons are tagged client-only in Next 16** (`Attempted to call the default export of lucide-react/Icon.mjs from the server`). When you need server-rendered (SSR'd-once-and-frozen) JSX, do NOT reuse existing components that import lucide. Either inline the icon as raw SVG, or omit the icon. Our `StaticCallout` simply skips the icon and uses a plain title + body — visually fine for static export.
  - **`server-only` package is NOT installed by default** in this project (Next 16 doesn't auto-pull it). Don't add `import 'server-only'` for documentation purposes — vitest will fail with `Cannot find package 'server-only'`. The createRequire trick alone suffices to satisfy Turbopack.
  - **`<script defer>` ordering matters for the static-client → loader → data.js chain**: with multiple `<script ... defer>` tags, browsers run them IN ORDER after the document is parsed. Putting the loader first (registers `window.runPython`), then the per-lesson data.js (sets `window.__AI_LECTURER_LESSON__`), then the static-client (consumes both) means the static-client always sees the lesson payload + loader. The static-client's `ready(fn)` helper checks `document.readyState !== 'loading'` and calls fn immediately — under defer this is always true, so DOMContentLoaded never has to fire to attach listeners.
  - **Selectors with two attributes need both attributes on the SAME element**. `[data-static-code-input][data-section-id="s-code"]` will NOT find a textarea that has only `data-static-code-input` even if the parent has `data-section-id="s-code"`. Add the data-section-id to every interactive descendant (input, output, status), not just the parent wrapper. (This bug cost ~30 minutes of debugging where the click handler was triggered but bailed out at the input/output null check.)
  - **archiver's default DEFLATE compression breaks naive ZIP central-directory readers**. Tests that read the ZIP back need a method-8 path (`require('node:zlib').inflateRawSync(compressed)`) or they'll throw on size-mismatch checks. The alternative is `archiver('zip', { store: true })` but that bloats the test fixtures unnecessarily.
  - **For Pyodide CDN fetch tests, `file://` is not enough** — Chromium blocks the cross-origin script load. Spin up a `python3 -m http.server <port>` rooted at the unzipped directory and `page.goto('http://localhost:<port>/<slug>/lessons/<lesson>.html')`. Spawn it via `child_process.spawn` with `detached: true` so you can kill it via `process.kill(-server.pid)` (the negative pid kills the process group) at test end without taking down the parent node process.
  - **Pyodide cold load on jsDelivr is ~3-7s**. Set the Playwright `waitForFunction` timeout for the "data-state=ok" selector to at least 60s (we use 90s) — running tests over a flaky network connection or a CDN that hasn't warmed up the file in your region can blow past 30s.
  - **`createRequire(import.meta.url)` unblocks any Turbopack import-time scan**. Generalisable pattern for "server-only Node module that Turbopack flags". Cache the resolved function in a module-level `let _foo = null` so repeated calls don't re-`require` (require itself caches by spec name, but the property access is still cheap).
