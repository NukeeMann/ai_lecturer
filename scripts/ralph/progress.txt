- **Learnings for future iterations:**
  - **TOCTOU between an async guard and async assignment** is a common pattern in Next route handlers that hold module-level state. The cheapest fix is a synchronous "reservation" boolean: set right after the check, cleared in `finally` once the real handle (here `activeRun`) is in place. NO await between guard and reservation set — that's the whole point.
  - When restructuring an `async` function to wrap its body in a try/finally, prefer extracting the body into a sibling `async startGenerationInner(...)` instead of indenting ~500 lines. Keeps the diff small and the existing logic unchanged.
  - Repro pattern for race-vs-await bugs in vitest: `Promise.allSettled([fn(...), fn(...)])` fires both tasks synchronously before any microtask runs. Each call's first `await` yields, giving the second call a chance to enter the same critical section. For this to actually exercise the race the inner `await` must yield to the event loop — `fs.mkdir(dir, {recursive:true})` does, even when the dir already exists.

Returns void on success (process is alive AND we have permission). The `try/catch` shape is `if (err.code === 'EPERM') return true; return false;` — never blanket-true on any error.
  - **Marker refresh inside `emit()`.** Updating `<courseDir>/.generating.json` on each `stage:started` event keeps the resume banner's `<stage>` label fresh even if the in-memory run is gone. Don't await the write inside emit (sync-emit invariant for listeners) — `void writeGeneratingMarker(...)` is fine because the marker is best-effort. Same pattern in `spawnChild` to refresh the PID. The seed write at run start handles the "tab reload happens between activeRun assignment and the first child spawn" gap.
  - **Removing the sendBeacon-on-unmount cancel.** A unmount-time `navigator.sendBeacon(`/api/courses/generate?id=${id}`)` that fires `DELETE` is incompatible with US-106's "agent doesn't stop on tab close" premise. We removed it — explicit Cancel button stays. If a future story actually wants per-tab "page hidden 5min, then auto-cancel" semantics, that needs a server-side timeout, not a client unmount hook (which fires too aggressively under SPA navigation, dev-mode StrictMode double-mount, route prefetch, etc.).
  - **`.generating.json` is fire-and-forget but the test must wait for the disk write.** The marker write inside emit/spawnChild is `void writeGeneratingMarker(...)` — no await. Unit tests that assert "the marker exists right after `await scripted.nextChild()`" need to poll for the file (try/parse/check childPid > 0) rather than a single `setImmediate` flush, because the awaited fs.mkdir + fs.writeFile may take several event-loop ticks.
  - **Suppression rule for the resume banner: `stage === 6 && submittedSlug === activeRun.slug`.** Hides the banner when the user is already on the resume target (Stage 6 for the same slug). Don't tie it to `stage === 6` alone — that hides the banner during a fresh/different generation flow too. Don't tie it to `submittedSlug === activeRun.slug` alone — that hides the banner before the user even reaches Stage 6 if the running slug happens to match the submittedSlug-from-?resume= param. The combined check is correct.
  - **`?resume=<slug>` is the cleanest deep-link.** No new route — just a query param the existing /create page reads on mount. Sets `submittedSlug` + `stage = 6`. Stage5Generate's effect handles attach via the existing idempotent POST /api/courses/generate path. No need to thread a new "resume" prop through the wizard.
  - **CourseStructure response uses `description`, not `summary`.** The structure stub for the playwright test must shape lessons as `{title, description, estimatedMinutes}` — `summary` is the field name on the *draft* edit-cascade variant after `courseStructureToDraft` translates it. Mixing the two surfaces only as a stage3-error console message and a black-hole "Generate course structure…" loading view that never completes.

- **Learnings for future iterations:**
  - **Three concurrent same-slug windows.** US-101 fixed the race between two POSTs both passing `if (activeRun)`. US-105 added the idempotent same-slug-already-active path. US-107 reveals a third: a second same-slug POST arriving AFTER `startingGeneration = true` but BEFORE `activeRun = run`. The pattern is: a synchronous "I'm starting slug X" identifier (`startingSlug`) so concurrent same-slug callers can recognize it and either wait for activeRun or return idempotent. Without this, React StrictMode dev double-mount would queue a duplicate as a separate entry.
  - **Lazy-loaded module state with persistence.** The queue lives in a module-scope `let queue: QueueEntry[]`. `ensureQueueLoaded()` runs once on first API call, then becomes a no-op (`queueLoaded` flag). `__resetForTesting()` clears the flag so tests start fresh. Same pattern would work for any future "persistent module state" — pin the file path via env var override, lazy-load on first use, reset in test teardown.
  - **Queue summary + drainer ordering.** Compute the queue snapshot for the response BEFORE calling the drainer — otherwise the drainer's synchronous `queue.shift()` removes the head before getQueueSummary serialises the response and the user sees an empty queue. Pattern: `await ensureQueueLoaded() → await computeSnapshot() → maybeStartDrainer()`. The IIFE inside maybeStartQueueHead synchronously enters its loop and calls `queue.shift()` BEFORE its first `await`, so deferring the drainer call by a single microtask wouldn't help — only ordering it after the snapshot does.
  - **Pop-then-start vs check-then-start.** The drainer pops the head BEFORE calling startGeneration, not after. This way, if startGeneration throws (claude unavailable, missing spec, schema parse error), the broken head is already gone and the loop tries the next entry without manual cleanup. `await persistQueue()` runs between shift and startGeneration so a server crash mid-start still leaves a consistent queue file.
  - **Stage5Generate state machine.** Adding `'queued'` to the phase union required careful audit of existing render branches: progress bar, log panel, cancel button. The cancel button was tied to `phase === 'running'` so it stays hidden in queued state — no need to thread queue-cancel semantics yet. The headline + subtext got two new branches (`phase === 'queued' ? 'Twoja generacja czeka w kolejce' : ...`). When a queued slug becomes active, the UI re-uses the same Stage5Generate machinery — just calls the existing `attachStream(id)` after a fresh idempotent POST to retrieve the run id.
  - **AC says queue is FIFO, but the response shape's `position` is 1-based.** The acceptance criteria use 1/1, 1/2, etc. — never 0/N. Both server-side `appendToQueue` and `queuePosition` use 1-based indices. `getQueueSummary` does the same. Don't accidentally use `queue.indexOf(slug)` (returns 0-based) when computing the response.
  - **POST /api/courses (`courseSpec` route) requires `summary` per lesson; POST /api/wizard/structure response uses `description` per lesson.** When constructing test specs directly via API (bypassing the wizard's draft→spec translation), use `summary`. When stubbing the structure endpoint, use `description`. Mixing the two is the silent-failure path noted in US-106's playwright learnings.
  - **POST /api/courses/active-run polling cadence.** 1.5s feels right: short enough that a queued user sees the transition within ~1.5s of slug B becoming active, slow enough to not hammer the route under WSL2 dev-mode latency. Don't poll faster than 1s — Turbopack rebuild lag amplifies and the SSE stream attach can race with redundant polls.
