## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.

- **`PythonError` shape (Pyodide 0.26).** A Pyodide exception thrown out of `runPythonAsync` is a `PythonError` (`err.constructor.name === 'PythonError'`, `err instanceof Error === true`). The headline `<Type>: <msg>` is the LAST non-empty line of `err.message`. - **Learnings for future iterations:**
  - When you stash with `git stash` and the working tree gets re-touched (e.g. `git checkout --` of a different file), `git stash pop` may print "no changes added to commit / The stash entry is kept" — that's NOT the same as "applied cleanly". If you also see "would be overwritten by merge" in the pop output, NOTHING was applied. Either commit/discard the conflicting working-tree changes first, or use `git stash apply <sha>` after dropping the conflict. If you accidentally `git stash drop` the still-unapplied stash, recover via `git fsck --no-reflogs --unreachable` → look for "unreachable commit" SHAs → `git show <sha> --stat` to identify it → `git stash apply <sha>` to restore. (Discovered the hard way mid-US-122.)
  - File-based course persistence (US-008 atomic write) reorders JSON keys when it round-trips through the API. Even when a playwright test "restores the original title", the lesson JSON's key order differs from the on-disk version. To leave a clean working tree after browser-testing CRUD on lesson JSON, do a final `git checkout -- courses/<slug>/lessons/<lesson>.json` before staging — the key reorder is semantic-noise, not a real change.
  - For "icon button at right edge of box" placement assertions, prefer measuring the gap from the button's right edge to the box's right edge (`box.right - btn.right`) instead of asserting on raw coordinates. That makes the assertion robust to viewport width changes and keeps the threshold (e.g. < 40px) intuitive: it's "the button is visually flush with the right edge of its container."
  - Don't reuse `EditorFormFooter` / `EditorFormSaveError` for in-box (mid-side-panel) action footers — those helpers style themselves with `borderTop` + `var(--bg-elevated)` background to look like a panel-bottom footer. When you want the buttons to sit INSIDE a card-shaped box, write a small inline footer with `var(--bg-subtle)` so it visually nests inside the card; otherwise the button row reads as a panel-level chrome bar and breaks the "this control belongs to the box" mental model the AC asks for.
