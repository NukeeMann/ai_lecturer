## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.
- Playwright skill at `scripts/ralph/skills/playwright-skill/` ships without `node_modules`; run `npm install --no-audit --no-fund` inside it before first use. Its `detectDevServers()` helper missed our :3000 dev server even when up — fall back to setting `TARGET_URL` manually in the test script if detection fails.
- **Zod is pinned to v3** (`^3.25.x`) because `zod-to-json-schema` returns an empty object on Zod v4. Don't bump zod to v4 unless the `zod-to-json-schema` import also changes. (Zod v4 has a native `z.toJSONSchema()`, but our AC mandates the third-party lib.)
- **Vitest needs its own alias config.** `vitest.config.ts` must declare `resolve.alias = { '@': fileURLToPath(new URL('./src', import.meta.url)) }`. Vitest does NOT read `tsconfig.json#paths`. Next + `tsc` + `tsx` (used by `npm run build:schemas`) DO auto-pick it up.
- **Eslint config does not exempt `_`-prefixed unused vars.** For "drop one field" test fixtures, use `const broken: Partial<typeof obj> = { ...obj }; delete broken.field;` — destructuring with `_name` triggers `@typescript-eslint/no-unused-vars` warnings.
- **Schema layout.** Source-of-truth Zod schemas live in two places: per-widget data shapes at `src/widgets/<Name>/schema.ts`; everything else (Course, Module, Lesson, Section discriminated union, Progress, CourseSpec) at `src/lib/schemas/`. `SectionSchema` is a `z.discriminatedUnion('type', […])` over `'theory'|'quiz'|'code'|'demo'|'sandbox'|'custom'`. Adding a new widget = new folder under `src/widgets/<Name>/` + register a variant in `src/lib/schemas/lesson.ts` + add it to the `widgets` map in `src/widgets/schemas/build.ts`. `npm run build:schemas` regenerates the committed `*.json` files in `src/widgets/schemas/`.
- **Filesystem helpers** live in `src/lib/server/` (server-only — never import from a `'use client'` module). `paths.ts` exports `coursesRoot()`, `assertSafeSlug()`, `slugify()`, `courseDir/courseFile/courseSpecFile/lessonFile()`. `atomic.ts` exports `atomicWriteJson(path, data)` (writes to `<path>.tmp` then `fs.rename`). `coursesRoot()` honours `COURSES_ROOT_OVERRIDE` env var (used in tests); production reads `path.join(process.cwd(), 'courses')`. Disk layout: `courses/<slug>/{course.json, course-spec.json, lessons/<lessonSlug>.json}`.
- **Next 16 route handlers + vitest.** Tests can import handlers directly from `src/app/api/.../route.ts` and call them with a synthesised `Request` and `{ params: Promise.resolve({...}) }` (Next 15+ wraps params in a Promise). `NextResponse.json()` returns a real `Response`, so `await res.json()` and `res.status` work in tests. Put the test file OUTSIDE `src/app/` (e.g. `src/lib/server/api.test.ts`) so Next doesn't try to compile it as a route — vitest's `include: 'src/**/*.test.ts'` still picks it up.
- **Slug rules.** `assertSafeSlug` rejects empty strings and any slug containing `/`, `\`, or `..` (path-traversal protection). Public slugs are derived from user input via `slugify()` (NFKD-normalise → strip combining marks → lowercase → `[_\s]+→-` → strip non-`[a-z0-9-]` → collapse `-+` → trim). Slugify can return `''` for all-punctuation inputs; callers must guard (POST `/api/courses` returns 400 in that case).
- **Pyodide worker singleton.** Web Workers are bundled by Turbopack via `new Worker(new URL('./worker.ts', import.meta.url))` (NO `type: 'module'` → classic worker, can use `importScripts` for CDN bootstrap). The worker file at `src/lib/pyodide/worker.ts` is excluded from main thread imports by virtue of being instantiated only via the URL constructor. Client hook lives at `src/lib/pyodide/client.ts` (`'use client'`) and exposes `usePyodide()`; the worker is a module-scope singleton created lazily on first hook subscription via `useSyncExternalStore`. Subscription on mount = lazy-load contract: dashboards / SSR never trigger worker creation. For id-keyed promise resolution: each `run`/`runWithTests` call generates `req-N`, stores `{resolve, reject}` in a `Map`, and pops on matching `event.data.id`. Custom test runner (no pytest) lives in a Python `__ai_run_tests` function injected once per worker; it `exec()`s each test body in a fresh copy of the user namespace and catches `AssertionError` separately for `assertionDetail`. Test results array shape: `[{name, passed, traceback?, assertionDetail?}]`.
- **CodeMirror 6 setup.** Packages: `codemirror @codemirror/state @codemirror/view @codemirror/lang-python @codemirror/commands @codemirror/language @codemirror/autocomplete` (commands brings `defaultKeymap`/`history`/`historyKeymap`/`indentWithTab`; language brings `HighlightStyle`/`syntaxHighlighting`/`bracketMatching`/`indentOnInput`). Theme via `EditorView.theme({...})` consuming our `--code-bg/--code-text/--code-keyword/...` CSS vars. Highlight via `HighlightStyle.define([{ tag: t.keyword, color: 'var(--code-keyword)' }, ...])` from `@lezer/highlight` tags. Editor instantiated once in `useEffect(() => {...}, [])` with `EditorState.create({doc, extensions:[…]})`; subsequent doc updates flow via `view.dispatch({changes:{from,to,insert}})`, NOT by re-rendering. Use `EditorView.updateListener.of((u)=>u.docChanged && setCode(u.state.doc.toString()))` to mirror doc into React state.
- **eslint react-hooks/refs rule is strict.** Never write `someRef.current = value` at component top level — must be inside `useEffect(() => { someRef.current = value; }, [value])` or inside an event handler. Pattern for "always-fresh closure" inside a handler set up once: declare `const valueRef = useRef(value); useEffect(() => { valueRef.current = value; }, [value]);` then read `valueRef.current` inside the long-lived closure.
- **Cmd/Ctrl+Enter in CodeMirror.** Use `keymap.of([{ key: 'Mod-Enter', preventDefault: true, run: () => { ...; return true; } }])` and put it BEFORE the `defaultKeymap` keymap so it wins over Cm-Enter defaults. `Mod` resolves to ⌘ on Mac and Ctrl elsewhere. Have the `run` callback dispatch via a ref (`handleRunRef.current()`) so it always picks up the latest closure.
- **Progress PATCH for sectionState.** PATCH `/api/progress` with body `{ courseSlug, lessonSlug, sectionState: { [sectionId]: { userCode } } }`. To CLEAR a section's state (e.g. on Reset), send `{ [sectionId]: {} }` — the server's `applyProgressPatch` shallow-merges into existing `sectionState[sectionId]` then replaces it, so `{}` overwrites and effectively wipes the entry's userCode. Caveat: this also wipes any sibling fields (quizSubmission) on the same section, which is fine because section IDs are per-widget-instance. To mark a section "done", PATCH `{ userCode, done: true }` together — `done?: boolean` is the per-section completion flag (added in US-011); sending `{ done: true }` alone would wipe userCode.
- **CodeRunner slots (US-011).** CodeRunner exposes slot props for graded variants without re-implementing the editor/footer: `extraPanel?: ReactNode` (rendered between output panel and footer), `primaryAction?: { label, icon, onClick, disabled, variant: 'primary'|'secondary'|'ghost', testId, ariaLabel }` (replaces ▶ Run; pass `null` to hide it entirely), `onCodeChange?: (code) => void` (mirror doc into parent state), `onReset?: () => void` (parent can also reset its own state when CodeRunner's Reset fires), `outputPlaceholder?: string`. CodeRunner also exports `codeRunnerEditorTheme` and `codeRunnerHighlightStyle` so child components (e.g. inline read-only test bodies) match the editor's look. Read-only CodeMirror needs BOTH `EditorState.readOnly.of(true)` and `EditorView.editable.of(false)`.

Use the native setter override: `Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set.call(el, '4'); el.dispatchEvent(new Event('input', { bubbles: true }));`. Same pattern works for `<select>`, `<textarea>`.

- **react-hooks/set-state-in-effect rule.** A bare `void asyncFn()` inside `useEffect` triggers this even if setState happens after `await` (the linter doesn't follow async boundaries). - **Learnings for future iterations:**
  - **Inline `<style>` tags inside repeating React subtrees pollute `textContent`.** TypingDots originally rendered `<style>{keyframes}</style>` inside its own span. The CSS string (~140 chars) was visible to `el.textContent` reads — making playwright's "wait until bubble has > N chars" check pass against the keyframes, NOT actual streamed tokens. Hoist single-instance keyframes to the panel root (or a non-text region) so element textContent reflects ONLY the user-visible string. Same trap applies to `<script>` tags.
  - **`claude -p "<prompt>"` (no `--output-format`) streams raw assistant text to stdout.** Each newline-terminated chunk is one paragraph/code-fence/list-line; total stream completes on process exit. For SSE we read line-by-line via `child.stdout.on('data', ...)` + buffer-and-split, NOT via `--output-format stream-json` (which emits per-message JSON envelopes and complicates parsing for what is essentially a passthrough).
  - **Two-channel cancel: client AbortController + server DELETE.** The Stop button does BOTH. `ac.abort()` on the client ends fetch reading immediately so the bubble freezes. `DELETE /api/lesson-chat/<requestId>` reaches across and kills the subprocess (or aborts the SDK iterator). Without DELETE, the server keeps the subprocess alive draining stdout into a closed stream until the OS reclaims it. Without ac.abort(), the client keeps draining and might process tokens that arrive AFTER the user clicked Stop. Both are necessary; neither alone is correct.
  - **Map<requestId, AbortController> in module scope IS the canonical "in-flight registry" for Next.js App Router.** No global server context exists; module-level state is the equivalent of a process-wide singleton (it's per-route-handler-module but Node only loads each module once per dev/prod server). Always wire a `_resetInflightForTesting()` so tests are deterministic — vitest workers share the module too.
  - **AbortController wired through ReadableStream's `cancel` callback handles client disconnect.** When the client closes the SSE connection (browser navigation, fetch abort, network drop), the runtime invokes `cancel()` on the ReadableStream. We call `abortController.abort()` + `unregisterInflight(requestId)` from there. This catches the case where the client never sent DELETE (e.g. tab close, Wi-Fi drop) — no leaked subprocess.
  - **SSE message frame parsing in TypeScript.** Frames are separated by `\n\n`. Each frame has lines starting with `event:` / `data:` / `id:` / `retry:` / `:` (comment). For our use, we only need `event:` and `data:`. Multiple `data:` lines in the same frame are joined with `\n` (per spec). Always `decoder.decode(value, { stream: true })` so multi-byte UTF-8 spanning chunks doesn't break, then a final `decoder.decode()` after the loop to flush the last partial sequence. Same pattern any token-streaming UI in this repo can adopt.
  - **`accumulated` closure-variable pattern for streaming setState.** Rather than reading-then-writing React state in each token handler, keep a local `let accumulated = ''` in the async closure, increment it sync, and call `setMessages(prev => ...)` with a snapshot. Reading state inside an async callback would race against React's batched updates; the local var is the source of truth for "what tokens have we received so far" and gets passed to `finalizeStopped`/the post-loop terminal `setMessages` once.
  - **Typed `Connector` interface gotcha for `vi.spyOn` mocks.** Adding `chatStream` to `Connector` broke every existing spy that returned `{ name, chat }`. Test helper `fakeConnector(chatImpl, streamImpl?)` papers over this by defaulting `chatStream` to a single-token-then-done generator built from `chat`. Adopt a similar helper any time the Connector contract grows so the existing spies stay one-line.
  - **Don't put debug `console.log` near token streaming in playwright tests UNLESS you also ingest them in the test.** I added `[chat-debug]` lines in the component, then teaches the playwright `page.on('console')` listener to surface them — that's how I noticed the TypingDots-textContent bug (catch path ran with `accumulated.length=0` even though the bubble seemed to have 142 chars of content).

- **Learnings for future iterations:**
  - **`lucide-react` icons render as `<svg>` with `display: block` by default.** Inside an `inline-block` parent that inherits `whiteSpace: pre-wrap` (e.g. anything inside `<pre style="whiteSpace: 'pre-wrap'">`), the SVG forces a line break after the preceding inline element. Symptom: icon renders BELOW the input even though DOM order says "after". Fix needs BOTH `whiteSpace: 'nowrap'` on the wrapper AND `display: 'inline-block'` (or `'inline'`) on the icon style. Either alone is insufficient — nowrap doesn't override block-level child display, and inline-block on the icon still wraps if the wrapper allows breaks.
  - **String-aware comment detection.** Naive `line.indexOf('#')` would falsely match `print("# not a comment")`. The walking parser (track `inStr` quote char, advance past `\\`-escapes, only test the prefix when not inside a string) is short enough — ~20 lines — that it's not worth pulling in a tokenizer dep. Same pattern works for `//` against single-/double-quoted JS strings; we tested both. Doesn't handle Python triple-quotes or template literals — fine for cloze line scope (cloze templates are line-by-line by definition).
  - **Line-based rendering inside `<pre>` with `whiteSpace: 'pre-wrap'`.** To inject a per-line trailing element while preserving newline-driven line breaks, render each line as a wrapper `<span>` containing the line's content + optional trailing element, then emit a literal `'\n'` text node between lines (skip the last). The `<pre>` parent renders the `\n` as a real line break. This sidesteps the React fragment-newline quirk where `<>{line}{'\n'}</>` works but `[line, '\n']` arrays sometimes don't preserve the newline properly across React reconciliation.
  - **Optional schema field rollout.** Adding `language: z.enum([...]).optional()` to a Zod data schema is a no-op for existing fixtures: `CodeClozeDataSchema.parse(rawData)` accepts records without the field, `validateSlotValue` is unaffected, and the helper defaults to `'python'` so `commentPrefix(undefined) → '#'`. No course migration needed. Don't forget to re-run `npm run build:schemas` so `src/widgets/schemas/code-cloze.json` reflects the new optional property — the json-schema is the contract for the LLM-side course-spec generation skill.
  - **Bug-fix story TDD pattern (revisited from US-057).** The cleanest "failing-test-before-fix" expression for a UI bug is: extract the broken decision into pure helpers and write tests for the FIXED behavior. Here `formatFeedbackComment` returning `"  # hint"` is the fixed contract; against the old widget code (which rendered a block span and never produced a comment string at all), that test would fail because the helper didn't exist yet. AC satisfied without spinning up jsdom + react-testing-library.
  - **`display: 'block'` on a hint span is the actual bug.** The README-level lesson here: when a parent renders an inline element trailing some other inline content, NEVER set the trailing element's display to `block` thinking "it'll just stack below" — yes it stacks, but it also disrupts inline-block parent sizing. If you want a line-break before the element, prefer a literal `'\n'` text node between siblings (under a `<pre>` ancestor) or a flex column container — but in this case, the entire premise was wrong: the hint should NOT be on a separate line, it should be an inline comment.
  - **Existing icons in `CodeClozeWidget` lacked test ids.** Added `data-testid="cloze-slot-icon-<id>"` + `data-icon="correct|incorrect"` for browser-test access. Generally: ANY decorative icon that has different states based on user input deserves a `data-testid` + `data-state` (or `data-icon`) attribute pair, even if no test currently uses it — bug-fix stories (this one) will need it within the lifetime of the codebase.
