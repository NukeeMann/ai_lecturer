- Learnings for future iterations:
  - **The Extend `/apply` route returns `{ enqueuedLessonSlugs }`, NOT the genId.** To wire whole-run Cancel, re-POST `/api/courses/generate { slug }` AFTER `/apply` returns — `enqueueGeneration` is idempotent for same-slug-already-active (US-107) so the second POST harmlessly returns `{ id, slug }` for the existing run, and then `DELETE /api/courses/generate?id=<id>` cancels via `run.cancel()`. Same trick Stage5Generate uses on `/create?resume=<slug>` re-entry.
  - **Polling `/api/courses/active-run` is good enough for per-lesson status without the SSE.** The active-run summary already exposes `progress.lessons[*].status` (pending|inflight|done|failed) from `.generation-state.json` (US-136). For a per-lesson status grid (no log-line streaming) this is dramatically simpler than reusing Stage5Generate's full SSE + ndjson replay flow, and the 1500ms poll cost is negligible. Use SSE only when you actually need the live log lines.
  - **"Run inactive but slug still in enqueuedLessonSlugs" is the run-completion signal.** When the poll returns `body.active === false || body.slug !== course.slug` and we haven't yet seen every slug flip to `done`, force-mark all non-failed enqueued slugs to `done`. Generation completion is a one-shot edge — by the time `getActiveRunSummary()` reports inactive, every lesson JSON for the just-finished run has been written. Polling `body.progress` alone would race the active→inactive transition and leave the last lesson stuck in `inflight`.
  - **Removing a top-level modal from page.tsx is a 3-step diff:** (1) drop the state (`extendTarget` / `setExtendTarget`), (2) drop the JSX render, (3) drop the component definitions AND any types/imports they used (`ExtendResponse`, `ExtendDialogPhase`, `ExtendChatMessage`). The third bullet is easy to miss when only doing a search-and-replace on the symbol name. Followed up with a static-source `extendModalRemoval.test.ts` so future PRs can't accidentally re-introduce it via copy-paste.
  - **`router.push(\`/courses/\${encodeURIComponent(course.slug)}/extend\`)` from inside a `useCallback` whose deps are `[router]`** is the canonical way to convert a modal-open handler into a navigation handler without touching CourseCardWithMenu / CollectionSection's prop shape. The `onRequestExtend(course)` prop and its `data-testid` survive unchanged so all the US-142 menu tests keep working.
  - **`view: 'edit' | 'progress'` as the top-level wizard view selector** keeps the AC promise of "same wizard page shell" trivially true — the header, breadcrumb, page-title, and bottom-bar layout don't move when `view` flips; only the content area swaps between the tree and the lesson-status grid. Same trick avoids needing a separate `/extend/generating` route.
