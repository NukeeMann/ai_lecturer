## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.
- Playwright skill at `scripts/ralph/skills/playwright-skill/` ships without `node_modules`; run `npm install --no-audit --no-fund` inside it before first use. Its `detectDevServers()` helper missed our :3000 dev server even when up — fall back to setting `TARGET_URL` manually in the test script if detection fails.

Adding a new widget = new folder under `src/widgets/<Name>/` + register a variant in `src/lib/schemas/lesson.ts` + add it to the `widgets` map in `src/widgets/schemas/build.ts`. `npm run build:schemas` regenerates the committed `*.json` files in `src/widgets/schemas/`.

To CLEAR a section's state (e.g. on Reset), send `{ [sectionId]: {} }` — the server's `applyProgressPatch` shallow-merges into existing `sectionState[sectionId]` then replaces it, so `{}` overwrites and effectively wipes the entry's userCode. To mark a section "done", PATCH `{ userCode, done: true }` together — `done?: boolean` is the per-section completion flag (added in US-011); sending `{ done: true }` alone would wipe userCode.

- **Cross-origin iframe postMessage spying is blocked.** Playwright (Chromium) throws `SecurityError: Blocked a frame with origin "..." from accessing a cross-origin frame` if you try to replace methods on `iframe.contentWindow` for a third-party embed (YouTube, Vimeo, etc.). - **Adding a new media type to course assets** = extend `CONTENT_TYPES` in `src/app/api/courses/[slug]/assets/[...path]/route.ts` (one map gates both the GET Content-Type header and the PUT extension allow-list). Currently supports `.png/.jpg/.jpeg/.svg/.webp/.gif/.mp4/.webm`.

- **`PythonError` shape (Pyodide 0.26).** A Pyodide exception thrown out of `runPythonAsync` is a `PythonError` (`err.constructor.name === 'PythonError'`, `err instanceof Error === true`). It exposes own properties `{ stack, message, type, __error_address }`. `err.type` is the Python exception class name as a string (`'ValueError'`, `'KeyboardInterrupt'`, etc.); `err.message` is the FULL formatted Python traceback ending in `<Type>: <msg>`. The headline `<Type>: <msg>` is the LAST non-empty line of `err.message`. Use `extractPythonError(err)` from `src/lib/pyodide/errorFormat.ts` to split into `{ traceback, errorType?, errorMessage? }` — do NOT lose `err.type`. `setStderr({ batched })` does NOT receive the traceback when an unhandled Python exception bubbles out: Pyodide hands the exception to the embedder (JS) instead, so `stderrBuf` stays empty and the only signal is the rejection. (Stderr IS captured for explicit `print(..., file=sys.stderr)`.)
- **Worker `RunResult` exception shape (US-061).** The worker spreads `...errorFields(err)` into the postMessage reply on every catch block in `worker.ts`, producing `{ stdout, stderr, traceback?, errorType?, errorMessage? }`. `client.ts` `RunResult` declares the new optional fields; consumers (`CodeRunner`, `CodeWidget`, `ParametricExplorer`) render the headline `<errorType>: <errorMessage>` in red with an inline "Show traceback" toggle that reveals the full multi-line trace. `extractPythonError` lives in `src/lib/pyodide/errorFormat.ts` and is unit-tested + Pyodide-integration-tested in `errorFormat.test.ts`.

  - **Course-author-facing courses use `data-quiz-option={i}` (no `data-testid`).** When playwright-targeting Quiz options, use `[data-quiz-option="N"]` and `[data-quiz-submit]`. This convention is older than the data-testid sweep and is unlikely to change. Other widgets follow similar `data-<widget>-<role>` patterns.
  - **`run.js` wraps loose code in `(async () => { ... })()` only when there's no `require(...)` line.** Don't write `module.exports = async ({page})=>...` — that signature is from another framework (and silently exits 0 with no output). Stick with raw scripts that `require('playwright')` and `chromium.launch()` themselves.
  - **The playwright-skill's working dir is the skill folder, NOT the repo root.** When invoking via `node scripts/ralph/skills/playwright-skill/run.js`, prefer the absolute path (`node /abs/.../run.js`) so the parent shell's pwd doesn't matter — `run.js` does `process.chdir(__dirname)` itself, but reaching it depends on the caller.

- **Learnings for future iterations:**
  - **`next/font/google` accepts `Source_Serif_4` (not `Source_Serif_Pro`).** The 4 = the variable-font version on Google Fonts. With variable fonts, `weight` can be omitted (the import returns the full axis range); for IBM Plex Sans (non-variable), you MUST specify `weight: ['400','500','600','700']` or the build fails. Use `display: 'swap'` so the FOUT/FOIT period falls back to the system stack — without `swap`, switching fonts shows blank text for ~100ms while the WOFF2 streams in.
  - **next/font CSS class shows the fallback name in computed `font-family`.** When asserting in playwright that a font is applied, expect e.g. `"IBM Plex Sans", "IBM Plex Sans Fallback", -apple-system, ...` — the `Fallback` entry is auto-generated by next/font with adjusted metrics to minimise CLS. A regex like `/IBM Plex/i` matches both the live font and its fallback, which is fine: the assertion is "the right family is in the chain", not "the live font has loaded by frame N".
  - **Adding a new theme axis (font, density, etc.) = 4 wiring points: layout.tsx imports + `<html>` className + boot-script branch + tokens.css selectors, plus the SettingsMenu group.** Skipping the boot-script branch causes a 1-frame flash after hydration; skipping the `<html>` className means the CSS variable `var(--font-ibm-plex)` is undefined and the chain falls through to system fonts (silent, hard to debug). Always grep for `data-density` in `layout.tsx` when adding a new axis — it's the canonical reference for all four wiring points.
  - **Add `--font-geist: var(--font-geist-sans)` alias in tokens.css** so the three fonts share a uniform `--font-<short>` naming convention. Without this, the data-font="geist" rule has to special-case `var(--font-geist-sans)` instead of `var(--font-geist)` like the others — minor, but the alias keeps the data-font selectors tidy and makes it obvious that all three slots are symmetric.
  - **Boot-script ordering matters when adding a new axis.** Place the new branch BETWEEN existing branches (here: after density, before accent) — order doesn't affect correctness but makes diffing easier and matches the visual order in the Settings dropdown.
