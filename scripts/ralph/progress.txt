- **Learnings for future iterations:**
  - **TOCTOU between an async guard and async assignment** is a common pattern in Next route handlers that hold module-level state. The cheapest fix is a synchronous "reservation" boolean: set right after the check, cleared in `finally` once the real handle (here `activeRun`) is in place. NO await between guard and reservation set — that's the whole point.
  - When restructuring an `async` function to wrap its body in a try/finally, prefer extracting the body into a sibling `async startGenerationInner(...)` instead of indenting ~500 lines. Keeps the diff small and the existing logic unchanged.
  - Repro pattern for race-vs-await bugs in vitest: `Promise.allSettled([fn(...), fn(...)])` fires both tasks synchronously before any microtask runs. Each call's first `await` yields, giving the second call a chance to enter the same critical section. For this to actually exercise the race the inner `await` must yield to the event loop — `fs.mkdir(dir, {recursive:true})` does, even when the dir already exists.

  - **claude -p stream-json requires `--verbose`** under the print-mode flag combo. Without `--verbose`, claude rejects the `--output-format stream-json` request. Order of args after `-p <prompt>` doesn't matter; pass them all as a flat argv list (no shell, so quoting is a non-issue).
  - **Stream-json event shape** (Claude Code 1.x): one JSON object per stdout line. Top-level `type` is `'system'` (init/lifecycle), `'assistant'` (model output — `message.content` is an array of `{type:'text',text}` / `{type:'tool_use',name,input}` / `{type:'thinking',thinking}` blocks), `'user'` (tool_result feedback — `message.content[].type === 'tool_result'` with either string content or an array of `{type:'text',text}` parts), or `'result'` (terminal summary — `subtype`, `is_error`, `duration_ms`, `result`, `cost_usd`). `pumpStream` already splits on `\n` so the line-by-line decoder bolts on cleanly.
  - **Pump-stream fan-out pattern.** When one raw line can produce N output lines (a multi-paragraph assistant text, a multi-block message), keep the existing buffer/split/flush loop and have `flushLine` iterate over the formatter's array. The `if (line.length === 0 && !stdoutBuf && !stderrBuf) continue;` guard inside the inner loop preserves the original "drop trailing empty line" behaviour without dropping legitimate decoded output.
  - **Don't bake raw JSON into the .generation.log file.** End-of-stage debugging is also easier when the persisted log shows decoded lines; if a future story needs the raw stream-json, capture it via a dedicated tee path rather than reverting the SSE-facing decode.
  - **Vitest stream-json fixture trick.** Constructing test events with `JSON.stringify({...}) + '\n'` reads better than hand-rolled string templates and stays in sync with TypeScript shape inference. `setImmediate`-based `tick()` between `emitStdout` calls forces pumpStream to flush each event before the next, so an assertion against `run.events` mid-flight reflects exactly what the SSE consumer would see at that instant. To prove the streaming is incremental (not batched), assert `init.exitCode === null` between emit and assertion.

- **Learnings for future iterations:**
  - **`Blob` constructor + Uint8Array under TS strict.** Tests that build a `File` from a `Uint8Array` for FormData must cast through `BlobPart`: `new Blob([content as BlobPart], …)`. The default `Uint8Array<ArrayBufferLike>` inferred type clashes with `Blob`'s `BlobPart = ArrayBufferView<ArrayBuffer>` constraint because `ArrayBufferLike` admits `SharedArrayBuffer`. The runtime is fine — only `tsc --noEmit` flags it.
  - **Optional fields piggy-backed on existing JSON request bodies** are the cheapest extension hook for Next route handlers when the body is already validated by zod. zod's default behaviour strips unknown keys, so adding `draftId` to the wire payload doesn't perturb the schema or the persisted spec — read it directly off the parsed `body` cast as `{ draftId?: unknown }`. No schema change, no migration.
  - **String-union stage state.** The wizard previously stored `stage: number`. Adding pre-flow steps (`'choose'`, `'materials'`) as numeric `0` and `0.5` would have polluted the existing Stepper jump logic; switching to a string union (`'choose' | 'materials' | 1..6`) and only running numeric-stage code under `typeof stage === 'number'` lets the new screens hide the stepper without touching the old branches at all.
  - **Browser file inputs whose change handler runs only once per file selection.** After `setInputFiles(...)`, programmatically clearing `e.target.value = ''` in `onInputChange` is REQUIRED if you want re-uploading the same file later in the same session to re-fire the change event — otherwise the browser dedupes against the prior `value`.
  - **`<coursesRoot>` is shared with GET /api/courses, and it iterates every directory entry under that root to find course.json.** Hidden dot-prefixed dirs like `.drafts/` get the same treatment, but the route silently skips on ENOENT for missing course.json — so the staging dir doesn't show up as a phantom course. Still: gitignore `/courses/.drafts/` so accidental commits during local testing don't pollute the repo.
  - **DraftId character class.** Reusing the slug regex (`[a-z0-9-]+`) is too permissive for IDs we mint server-side (they go straight to the URL). The dedicated `^[a-zA-Z0-9-]{6,64}$` class lets `crypto.randomUUID()` ids through (mixed-case UUIDs from older Node versions) while still rejecting `..`, `/`, `\`, and empty strings.
  - **MIME type fallback for office documents.** Browsers (especially older Firefox) sometimes report `application/octet-stream` or `''` for `.pptx`/`.docx` because they don't have those types in `mime.types`. Treat extension as authoritative: per-extension MIME allow-list PLUS a small fallback set (`'', 'application/octet-stream'`). Without this fallback, our own playwright test would intermittently 400 the server because `setInputFiles` doesn't set `type` on the synthetic File for unrecognized extensions.
