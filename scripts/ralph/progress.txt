## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. - **`PythonError` shape (Pyodide 0.26).** A Pyodide exception thrown out of `runPythonAsync` is a `PythonError` (`err.constructor.name === 'PythonError'`, `err instanceof Error === true`). It exposes own properties `{ stack, message, type, __error_address }`. `err.type` is the Python exception class name as a string (`'ValueError'`, `'KeyboardInterrupt'`, etc.); `err.message` is the FULL formatted Python traceback ending in `<Type>: <msg>`. The headline `<Type>: <msg>` is the LAST non-empty line of `err.message`. Use `extractPythonError(err)` from `src/lib/pyodide/errorFormat.ts` to split into `{ traceback, errorType?, errorMessage? }` — do NOT lose `err.type`. `setStderr({ batched })` does NOT receive the traceback when an unhandled Python exception bubbles out: Pyodide hands the exception to the embedder (JS) instead, so `stderrBuf` stays empty and the only signal is the rejection. - **Learnings for future iterations:**
  - There are THREE separate markdown-rendering paths that each need a widget feature wired independently: (1) src/widgets/Theory/TheoryWidget.tsx (live, client, full interactivity), (2) src/app/courses/[slug]/lessons/[lessonSlug]/print/page.tsx (server-rendered print page that puppeteer PDFs — client components DO hydrate here), (3) src/lib/export/staticRender.tsx (renderToStaticMarkup → static HTML + vanilla JS, NO React hydration). A new markdown feature (callouts, mermaid, …) generally needs touching all three. The first two can share a client component; the static one needs a vanilla/CDN equivalent.
  - To intercept fenced code blocks in react-markdown v10, override the `pre` component (not `code`): the `pre` child is the `<code>` element whose `className` carries `language-xxx`. Returning a `<div>` from the `code` override would nest a div inside `<pre>` (invalid). The shared helper is `MermaidPre` in src/components/MermaidDiagram.tsx.
  - Static export CDN pattern: emit a marker element + a loader script in assets/ that imports the lib from jsDelivr. pyodide-loader.js is a classic `<script defer>`; mermaid ships ESM only, so mermaid-loader.js must be `<script type="module">` with a top-level `import`. Pin the CDN version to the installed package version (MERMAID_VERSION) for determinism.
  - Puppeteer + client-rendered content: `networkidle0` is not enough for post-hydration async rendering. Have the client component expose a DOM state attribute (`data-mermaid-state`) and `page.waitForFunction` on it before `page.pdf()`. Keep the wait best-effort (try/catch + timeout) so a hang never fails the export.
  - Mermaid theming: use `theme:'base'` + `themeVariables` populated from `getComputedStyle(document.documentElement).getPropertyValue('--token')`. This binds the palette to whatever theme/accent is active and is the only way to get light/dark/sunset legibility from one code path. `securityLevel:'strict'` is safe for flowchart/sequence/mindmap.
  - HMR gotcha: right after editing an API route.ts, the very next request can transiently 404 with the app not-found HTML before Turbopack finishes recompiling. Re-request after a moment before concluding a route is broken.
