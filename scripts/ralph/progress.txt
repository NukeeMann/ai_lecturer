## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. - **`PythonError` shape (Pyodide 0.26).** A Pyodide exception thrown out of `runPythonAsync` is a `PythonError` (`err.constructor.name === 'PythonError'`, `err instanceof Error === true`). The headline `<Type>: <msg>` is the LAST non-empty line of `err.message`. - **Learnings for future iterations:**
  - **Process-group kill already works via `killChildTree()`** in `generation.ts`. The existing `cancel()` plumbing uses `process.kill(-pid, signal)` because every spawn is launched with `detached:true`. Pause reuses the same helper — no new "find all subagents" logic was needed. The fake-child test mocks (`FakeChildProcess`) bypass the `instanceof RealChildProcess` gate so the test runner's real PID space is never touched.
  - **`pausedInflightLesson` must be captured synchronously inside `pause()`, not asynchronously inside the pipeline.** The pipeline check (`if (paused) finalizePaused()`) runs AFTER spawnChild resolves; by then `currentChild` is null and `run.currentStage` may have moved to a new stage's `started` if the kill races with the next emit. Capturing the slug at pause-click time via `run.currentStage.startsWith('lesson:')` is the only reliable read. For per-test determinism the FakeChildProcess.kill() handler also calls `finishWithExit(143)` immediately on SIGTERM so the pipeline sees the kill without us racing a SIGKILL timer.
  - **Test mock's SIGTERM behavior.** Real `claude -p` traps SIGTERM and does a graceful flush before SIGKILL escalates; the test mock can't model that AND keep tests fast, so I patched `FakeChildProcess.kill()` to collapse SIGTERM → immediate exit(143). The production sigkillGraceMs path is exercised separately by the cancel-cooldown tests; pause-specific tests don't need to wait wall-clock seconds for the escalation.
  - **`finalizePaused()` deletes the in-flight lesson JSON BEFORE persisting the state file.** Order matters for crash recovery: if the unlink succeeds but the state write crashes, the next read sees a stale `inflight` lesson with no file on disk — `isLessonAlreadyValid()` will return `{valid:false, reason:'missing'}` and the resume path will re-spawn the lesson, which is the desired conservative behaviour. Reversing the order would risk persisting `paused` while leaving the partial JSON, which `isLessonAlreadyValid()` would happily accept on resume (if it happens to parse) and silently skip the regeneration.
  - **AC wording "Pause podczas stage init → Resume re-runuje init_course" is a single-stage shorthand for the actually-two-stage init pipeline.** US-192 noted the pipeline split research_course + design_course out of the original init_course. My implementation re-runs whichever init stage was incomplete: pause during research → research re-runs (then design); pause during design (with research already done) → only design re-runs. Both satisfy the AC's intent.
  - **Optional schema fields don't need a schemaVersion bump.** `status` and `pausedInflightLesson` are `.optional()` in GenerationStateSchema. Pre-US-194 `.generation-state.json` files lack both fields entirely — zod's `.optional()` accepts that gracefully, so `readGenerationState()` keeps reading older files without a migration. The reverse (a US-194 state file read by older code) doesn't happen here because there's no older-code consumer in the deployment.
  - **`isLessonAlreadyValid` is the implicit safety net for the pause→resume race window.** If pause lands at the exact instant a lesson finishes (atomicWriteJson succeeded, but `if (paused)` check fires before the state-update block), finalizePaused() unlinks the just-written file and resets the lesson to pending. Resume sees pending → isLessonAlreadyValid → missing → spawns a fresh attempt. The lesson is regenerated, which costs tokens but is correct. The alternative (preserving the lesson) would require detecting the race and treating it as "no-op pause", which adds complexity without practical benefit — the user's intent on Pause is "stop NOW", losing one lesson's worth of work is the price of that semantic.
