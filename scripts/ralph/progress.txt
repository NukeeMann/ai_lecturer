## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.
- Playwright skill at `scripts/ralph/skills/playwright-skill/` ships without `node_modules`; run `npm install --no-audit --no-fund` inside it before first use. Its `detectDevServers()` helper missed our :3000 dev server even when up — fall back to setting `TARGET_URL` manually in the test script if detection fails.
- **Zod is pinned to v3** (`^3.25.x`) because `zod-to-json-schema` returns an empty object on Zod v4. Don't bump zod to v4 unless the `zod-to-json-schema` import also changes. (Zod v4 has a native `z.toJSONSchema()`, but our AC mandates the third-party lib.)
- **Vitest needs its own alias config.** `vitest.config.ts` must declare `resolve.alias = { '@': fileURLToPath(new URL('./src', import.meta.url)) }`. Vitest does NOT read `tsconfig.json#paths`. Next + `tsc` + `tsx` (used by `npm run build:schemas`) DO auto-pick it up.
- **Eslint config does not exempt `_`-prefixed unused vars.** For "drop one field" test fixtures, use `const broken: Partial<typeof obj> = { ...obj }; delete broken.field;` — destructuring with `_name` triggers `@typescript-eslint/no-unused-vars` warnings.
- **Schema layout.** Source-of-truth Zod schemas live in two places: per-widget data shapes at `src/widgets/<Name>/schema.ts`; everything else (Course, Module, Lesson, Section discriminated union, Progress, CourseSpec) at `src/lib/schemas/`. `SectionSchema` is a `z.discriminatedUnion('type', […])` over `'theory'|'quiz'|'code'|'demo'|'sandbox'|'custom'`. Adding a new widget = new folder under `src/widgets/<Name>/` + register a variant in `src/lib/schemas/lesson.ts` + add it to the `widgets` map in `src/widgets/schemas/build.ts`. `npm run build:schemas` regenerates the committed `*.json` files in `src/widgets/schemas/`.
- **Filesystem helpers** live in `src/lib/server/` (server-only — never import from a `'use client'` module). `paths.ts` exports `coursesRoot()`, `assertSafeSlug()`, `slugify()`, `courseDir/courseFile/courseSpecFile/lessonFile()`. `atomic.ts` exports `atomicWriteJson(path, data)` (writes to `<path>.tmp` then `fs.rename`). `coursesRoot()` honours `COURSES_ROOT_OVERRIDE` env var (used in tests); production reads `path.join(process.cwd(), 'courses')`. Disk layout: `courses/<slug>/{course.json, course-spec.json, lessons/<lessonSlug>.json}`.
- **Next 16 route handlers + vitest.** Tests can import handlers directly from `src/app/api/.../route.ts` and call them with a synthesised `Request` and `{ params: Promise.resolve({...}) }` (Next 15+ wraps params in a Promise). `NextResponse.json()` returns a real `Response`, so `await res.json()` and `res.status` work in tests. Put the test file OUTSIDE `src/app/` (e.g. `src/lib/server/api.test.ts`) so Next doesn't try to compile it as a route — vitest's `include: 'src/**/*.test.ts'` still picks it up.
- **Slug rules.** `assertSafeSlug` rejects empty strings and any slug containing `/`, `\`, or `..` (path-traversal protection). Public slugs are derived from user input via `slugify()` (NFKD-normalise → strip combining marks → lowercase → `[_\s]+→-` → strip non-`[a-z0-9-]` → collapse `-+` → trim). Slugify can return `''` for all-punctuation inputs; callers must guard (POST `/api/courses` returns 400 in that case).
- **Pyodide worker singleton.** Web Workers are bundled by Turbopack via `new Worker(new URL('./worker.ts', import.meta.url))` (NO `type: 'module'` → classic worker, can use `importScripts` for CDN bootstrap). The worker file at `src/lib/pyodide/worker.ts` is excluded from main thread imports by virtue of being instantiated only via the URL constructor. Client hook lives at `src/lib/pyodide/client.ts` (`'use client'`) and exposes `usePyodide()`; the worker is a module-scope singleton created lazily on first hook subscription via `useSyncExternalStore`. Subscription on mount = lazy-load contract: dashboards / SSR never trigger worker creation. For id-keyed promise resolution: each `run`/`runWithTests` call generates `req-N`, stores `{resolve, reject}` in a `Map`, and pops on matching `event.data.id`. Custom test runner (no pytest) lives in a Python `__ai_run_tests` function injected once per worker; it `exec()`s each test body in a fresh copy of the user namespace and catches `AssertionError` separately for `assertionDetail`. Test results array shape: `[{name, passed, traceback?, assertionDetail?}]`.
- **CodeMirror 6 setup.** Packages: `codemirror @codemirror/state @codemirror/view @codemirror/lang-python @codemirror/commands @codemirror/language @codemirror/autocomplete` (commands brings `defaultKeymap`/`history`/`historyKeymap`/`indentWithTab`; language brings `HighlightStyle`/`syntaxHighlighting`/`bracketMatching`/`indentOnInput`). Theme via `EditorView.theme({...})` consuming our `--code-bg/--code-text/--code-keyword/...` CSS vars. Highlight via `HighlightStyle.define([{ tag: t.keyword, color: 'var(--code-keyword)' }, ...])` from `@lezer/highlight` tags. Editor instantiated once in `useEffect(() => {...}, [])` with `EditorState.create({doc, extensions:[…]})`; subsequent doc updates flow via `view.dispatch({changes:{from,to,insert}})`, NOT by re-rendering. Use `EditorView.updateListener.of((u)=>u.docChanged && setCode(u.state.doc.toString()))` to mirror doc into React state.
- **eslint react-hooks/refs rule is strict.** Never write `someRef.current = value` at component top level — must be inside `useEffect(() => { someRef.current = value; }, [value])` or inside an event handler. Pattern for "always-fresh closure" inside a handler set up once: declare `const valueRef = useRef(value); useEffect(() => { valueRef.current = value; }, [value]);` then read `valueRef.current` inside the long-lived closure.
- **Cmd/Ctrl+Enter in CodeMirror.** Use `keymap.of([{ key: 'Mod-Enter', preventDefault: true, run: () => { ...; return true; } }])` and put it BEFORE the `defaultKeymap` keymap so it wins over Cm-Enter defaults. `Mod` resolves to ⌘ on Mac and Ctrl elsewhere. Have the `run` callback dispatch via a ref (`handleRunRef.current()`) so it always picks up the latest closure.
- **Progress PATCH for sectionState.** PATCH `/api/progress` with body `{ courseSlug, lessonSlug, sectionState: { [sectionId]: { userCode } } }`. To CLEAR a section's state (e.g. on Reset), send `{ [sectionId]: {} }` — the server's `applyProgressPatch` shallow-merges into existing `sectionState[sectionId]` then replaces it, so `{}` overwrites and effectively wipes the entry's userCode. Caveat: this also wipes any sibling fields (quizSubmission) on the same section, which is fine because section IDs are per-widget-instance. To mark a section "done", PATCH `{ userCode, done: true }` together — `done?: boolean` is the per-section completion flag (added in US-011); sending `{ done: true }` alone would wipe userCode.

- **Learnings for future iterations:**
  - **Singleton survival across recreations.** When a module-level singleton can be recreated mid-life (here: terminate + spawn fresh worker), hoist its OUTWARD-FACING listener sets and current-state vars OUT of the singleton. Otherwise the React subscribers from `useSyncExternalStore` get orphaned the moment you null the singleton. Pattern: `const statusListeners = new Set<...>(); let currentStatus = 'idle'; let singleton: WorkerSingleton | null = null;` — listeners and status outlive the worker.
  - **Identity-check stale events.** When you replace a singleton, in-flight events from the OLD instance can still arrive on its listeners (race: `terminate()` doesn't drain queued postMessages). Guard every listener with `if (singleton !== obj) return;` before mutating shared state. Otherwise a late `'ready'` from an old worker will flip your fresh-worker status incorrectly.
  - **Fake-timer-aware setTimeout in vitest.** `window.setTimeout` returns `number` under the `dom` lib (no `@types/node`); `setTimeout` (bare) returns `Timeout`. Pick one and stick with it — mixing causes `TS2322 Type 'number' is not assignable to type 'Timeout'`. We use `let timer: number | null = null` because the singleton always calls `window.setTimeout` (it's gated on `typeof window !== 'undefined'`). `vi.useFakeTimers()` mocks both via the `globalThis.setTimeout` shim, so tests work as long as the shim assigns `globalThis.window = globalThis`.
  - **Errors-with-reason for caller-distinguishable rejections.** When one rejection path serves multiple use cases (Stop button vs auto-timeout), thread the reason through a custom Error subclass with a typed field. `if (err instanceof PyodideStopError) { ... err.reason }` is much cleaner than parsing `err.message`. Bonus: keeps the unhappy path strongly typed.
  - **Restart event vs error catch.** When a parent component owns the in-flight call but the child renders the "we restarted" UI (here: CodeWidget owns runWithTests, CodeRunner shows the Callout), an error catch alone doesn't reach the child. Solution: emit a global event from the singleton (`subscribePyodideRestart`), have the child subscribe, and only act if the child knows it had something in flight (gate on `runningRef.current || actionRunningRef.current`). This pattern generalizes to any "shared resource was forcibly reset" scenario where multiple components need to know.
  - **`__test` export pattern.** When a module's testable surface needs internals (here: spawning the worker without rendering React), expose a single `__test` namespace at the bottom of the file with the minimum hooks.   - **Adding an optional field to the section discriminated-union base.** `sectionBase` is a `const sectionBase = { id, title }` spread into each variant's `z.object({...sectionBase, type: z.literal(...), data: ... })`. To add a field common to every section type, add it to `sectionBase` — the spread propagates to every variant and `zodToJsonSchema` emits one canonical definition with `$ref`s under each variant. Don't try to wrap the whole `discriminatedUnion` in another schema; you'll lose the discriminant.

Five near-identical 5-line patches; no shared base needed.

  - **`headerActions` composition pattern.** The `Widget` component's `headerActions` slot accepts a single `ReactNode`, but multiple actions (sources popover trigger + edit pencil) need to live there. Compose with a fragment: `headerActions = sourcesNode || pencilNode ? <>{sourcesNode}{pencilNode}</> : undefined;` — `Widget`'s wrapper div uses `gap: 4`, so siblings inside the fragment get the same spacing automatically.
  - **`zod-to-json-schema` URL format.** `z.string().url()` becomes `{"type": "string", "format": "uri"}` in the JSON Schema output — the field is checked at runtime by Zod's `URL` constructor, not by the JSON Schema validator unless that validator opts into format-checking. Good enough for our use case (we do `LessonSchema.parse()` server-side).
