## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.
- Playwright skill at `scripts/ralph/skills/playwright-skill/` ships without `node_modules`; run `npm install --no-audit --no-fund` inside it before first use. Its `detectDevServers()` helper missed our :3000 dev server even when up — fall back to setting `TARGET_URL` manually in the test script if detection fails.
- **Zod is pinned to v3** (`^3.25.x`) because `zod-to-json-schema` returns an empty object on Zod v4. Don't bump zod to v4 unless the `zod-to-json-schema` import also changes. (Zod v4 has a native `z.toJSONSchema()`, but our AC mandates the third-party lib.)
- **Vitest needs its own alias config.** `vitest.config.ts` must declare `resolve.alias = { '@': fileURLToPath(new URL('./src', import.meta.url)) }`. Vitest does NOT read `tsconfig.json#paths`. Next + `tsc` + `tsx` (used by `npm run build:schemas`) DO auto-pick it up.
- **Eslint config does not exempt `_`-prefixed unused vars.** For "drop one field" test fixtures, use `const broken: Partial<typeof obj> = { ...obj }; delete broken.field;` — destructuring with `_name` triggers `@typescript-eslint/no-unused-vars` warnings.
- **Schema layout.** Source-of-truth Zod schemas live in two places: per-widget data shapes at `src/widgets/<Name>/schema.ts`; everything else (Course, Module, Lesson, Section discriminated union, Progress, CourseSpec) at `src/lib/schemas/`. `SectionSchema` is a `z.discriminatedUnion('type', […])` over `'theory'|'quiz'|'code'|'demo'|'sandbox'|'custom'`. Adding a new widget = new folder under `src/widgets/<Name>/` + register a variant in `src/lib/schemas/lesson.ts` + add it to the `widgets` map in `src/widgets/schemas/build.ts`. `npm run build:schemas` regenerates the committed `*.json` files in `src/widgets/schemas/`.
- **Filesystem helpers** live in `src/lib/server/` (server-only — never import from a `'use client'` module). `paths.ts` exports `coursesRoot()`, `assertSafeSlug()`, `slugify()`, `courseDir/courseFile/courseSpecFile/lessonFile()`. `atomic.ts` exports `atomicWriteJson(path, data)` (writes to `<path>.tmp` then `fs.rename`). `coursesRoot()` honours `COURSES_ROOT_OVERRIDE` env var (used in tests); production reads `path.join(process.cwd(), 'courses')`. Disk layout: `courses/<slug>/{course.json, course-spec.json, lessons/<lessonSlug>.json}`.
- **Next 16 route handlers + vitest.** Tests can import handlers directly from `src/app/api/.../route.ts` and call them with a synthesised `Request` and `{ params: Promise.resolve({...}) }` (Next 15+ wraps params in a Promise). `NextResponse.json()` returns a real `Response`, so `await res.json()` and `res.status` work in tests. Put the test file OUTSIDE `src/app/` (e.g. `src/lib/server/api.test.ts`) so Next doesn't try to compile it as a route — vitest's `include: 'src/**/*.test.ts'` still picks it up.
- **Slug rules.** `assertSafeSlug` rejects empty strings and any slug containing `/`, `\`, or `..` (path-traversal protection). Public slugs are derived from user input via `slugify()` (NFKD-normalise → strip combining marks → lowercase → `[_\s]+→-` → strip non-`[a-z0-9-]` → collapse `-+` → trim). Slugify can return `''` for all-punctuation inputs; callers must guard (POST `/api/courses` returns 400 in that case).
- **Pyodide worker singleton.** Web Workers are bundled by Turbopack via `new Worker(new URL('./worker.ts', import.meta.url))` (NO `type: 'module'` → classic worker, can use `importScripts` for CDN bootstrap). The worker file at `src/lib/pyodide/worker.ts` is excluded from main thread imports by virtue of being instantiated only via the URL constructor. Client hook lives at `src/lib/pyodide/client.ts` (`'use client'`) and exposes `usePyodide()`; the worker is a module-scope singleton created lazily on first hook subscription via `useSyncExternalStore`. Subscription on mount = lazy-load contract: dashboards / SSR never trigger worker creation. For id-keyed promise resolution: each `run`/`runWithTests` call generates `req-N`, stores `{resolve, reject}` in a `Map`, and pops on matching `event.data.id`. Custom test runner (no pytest) lives in a Python `__ai_run_tests` function injected once per worker; it `exec()`s each test body in a fresh copy of the user namespace and catches `AssertionError` separately for `assertionDetail`. Test results array shape: `[{name, passed, traceback?, assertionDetail?}]`.
- **CodeMirror 6 setup.** Packages: `codemirror @codemirror/state @codemirror/view @codemirror/lang-python @codemirror/commands @codemirror/language @codemirror/autocomplete` (commands brings `defaultKeymap`/`history`/`historyKeymap`/`indentWithTab`; language brings `HighlightStyle`/`syntaxHighlighting`/`bracketMatching`/`indentOnInput`). Theme via `EditorView.theme({...})` consuming our `--code-bg/--code-text/--code-keyword/...` CSS vars. Highlight via `HighlightStyle.define([{ tag: t.keyword, color: 'var(--code-keyword)' }, ...])` from `@lezer/highlight` tags. Editor instantiated once in `useEffect(() => {...}, [])` with `EditorState.create({doc, extensions:[…]})`; subsequent doc updates flow via `view.dispatch({changes:{from,to,insert}})`, NOT by re-rendering. Use `EditorView.updateListener.of((u)=>u.docChanged && setCode(u.state.doc.toString()))` to mirror doc into React state.
- **eslint react-hooks/refs rule is strict.** Never write `someRef.current = value` at component top level — must be inside `useEffect(() => { someRef.current = value; }, [value])` or inside an event handler. Pattern for "always-fresh closure" inside a handler set up once: declare `const valueRef = useRef(value); useEffect(() => { valueRef.current = value; }, [value]);` then read `valueRef.current` inside the long-lived closure.
- **Cmd/Ctrl+Enter in CodeMirror.** Use `keymap.of([{ key: 'Mod-Enter', preventDefault: true, run: () => { ...; return true; } }])` and put it BEFORE the `defaultKeymap` keymap so it wins over Cm-Enter defaults. `Mod` resolves to ⌘ on Mac and Ctrl elsewhere. Have the `run` callback dispatch via a ref (`handleRunRef.current()`) so it always picks up the latest closure.
- **Progress PATCH for sectionState.** PATCH `/api/progress` with body `{ courseSlug, lessonSlug, sectionState: { [sectionId]: { userCode } } }`. To CLEAR a section's state (e.g. on Reset), send `{ [sectionId]: {} }` — the server's `applyProgressPatch` shallow-merges into existing `sectionState[sectionId]` then replaces it, so `{}` overwrites and effectively wipes the entry's userCode. Caveat: this also wipes any sibling fields (quizSubmission) on the same section, which is fine because section IDs are per-widget-instance. To mark a section "done", PATCH `{ userCode, done: true }` together — `done?: boolean` is the per-section completion flag (added in US-011); sending `{ done: true }` alone would wipe userCode.
- **CodeRunner slots (US-011).** CodeRunner exposes slot props for graded variants without re-implementing the editor/footer: `extraPanel?: ReactNode` (rendered between output panel and footer), `primaryAction?: { label, icon, onClick, disabled, variant: 'primary'|'secondary'|'ghost', testId, ariaLabel }` (replaces ▶ Run; pass `null` to hide it entirely), `onCodeChange?: (code) => void` (mirror doc into parent state), `onReset?: () => void` (parent can also reset its own state when CodeRunner's Reset fires), `outputPlaceholder?: string`. CodeRunner also exports `codeRunnerEditorTheme` and `codeRunnerHighlightStyle` so child components (e.g. inline read-only test bodies) match the editor's look. Read-only CodeMirror needs BOTH `EditorState.readOnly.of(true)` and `EditorView.editable.of(false)`.
- **TS target ES2017.** The regex `s` (dotAll) flag triggers `TS1501`. Use `[\s\S]` in patterns that need to span newlines, never `/.../s`.
- **Lesson navigation.** Flat ordered lesson list = `course.modules.flatMap(m => m.lessons)`. Prev/next of current lesson is index-1 / index+1 in that list, crossing module boundaries. Client navigation uses `router.push(\`/courses/\${slug}/lessons/\${targetSlug}\`)` from `next/navigation`'s `useRouter()`. Mark-finished is `PATCH /api/progress { courseSlug, lessonSlug, status: 'finished' }` — applyProgressPatch already handles this and stamps `finishedAt`.
- **Adding a new widget type = 5 mandatory wiring points** (see `src/widgets/README.md`): (1) `--widget-<name>` CSS var in both light + dark blocks of `src/styles/tokens.css`; (2) Zod data schema at `src/widgets/<Name>/schema.ts` + register in `src/widgets/schemas/build.ts` so `npm run build:schemas` emits `<name>.json`; (3) `widgetRegistry` entry in `src/widgets/registry.ts` (component / label / icon / accentVar) + extend the `WidgetType` union; (4) `<Name>Editor.tsx` per US-023 pattern + import + branch in both `WidgetEditPanel` and `SectionRenderer` in `src/app/courses/[slug]/lessons/[lessonSlug]/page.tsx`; (5) `<Name>SectionSchema` variant in `SectionSchema` discriminated union at `src/lib/schemas/lesson.ts`. Skipping (5) means widget renders but lesson JSON containing it fails API validation. Histogram (US-030) is the canonical reference implementation.
- **React-aware playwright slider input.** Setting `el.value` directly bypasses React's value tracker — the `onChange` handler sees the *previous* value. Use the native setter override: `Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set.call(el, '4'); el.dispatchEvent(new Event('input', { bubbles: true }));`. Same pattern works for `<select>`, `<textarea>`.
- **Pyodide lesson namespace + test isolation (US-031).** Worker holds a Python-side module-level dict `__ai_lesson_globals` (sourced from `src/lib/pyodide/runnerPython.ts` so vitest can re-install it via the `pyodide` npm dev-dep). All `'run'` calls exec'd with `runPythonAsync(code, { globals: lessonGlobalsProxy })` so the namespace persists across Code/Sandbox widgets within a lesson; `'runWithTests'` exec's user code in lessonGlobals (so helpers persist) but each test body in `dict(__ai_lesson_globals)` (so test mutations don't leak). `'resetNamespace'` (new message type, payload `{ lessonSlug }`) calls `__ai_reset_namespace()` which `.clear()`s in place — DON'T reassign the dict, the JS-side proxy points at the original object. Lesson page calls `usePyodide().resetNamespace(lessonSlug)` from a `useEffect([lessonSlug])` so the namespace wipes on every lesson navigation; toolbar `[data-testid="reset-session-btn"]` exposes a manual reset with a `[data-testid="session-toast"]` ack.
- **Browser tests touching Code/Sandbox widgets must clear `~/.ai-lecturer/progress.json` per-section state first.** Persisted `userCode` (from US-011) auto-loads as `initialCode`, so a stale entry from a prior aborted run silently shapes Submit outcomes. Wipe via `node -e` JSON edit or use a throwaway course slug.
- **CodeMirror typing in playwright auto-indents on `\n`.** `keyboard.type('def f():\\n    return 42\\n')` produces compound indents. Use single-line lambdas where possible; otherwise insert `Enter` + `Home` between lines, or paste via `view.dispatch({changes:{...}})`.
- **Pyodide batched stdout strips `\n` (US-032).** `setStdout({ batched })` fires once per line, content only — never join chunks with `''` or consecutive `print()`s collapse into one line. Use the `formatStdoutChunks` helper at `src/lib/pyodide/stdout.ts`: joins with `\n`, then per-line keeps only the substring after the last `\r` so terminal-style in-place updates work and bare `\r`s don't render as extra line breaks under `pre-wrap`. The CodeRunner output panel already uses `whiteSpace: 'pre-wrap'`, so once newlines actually exist in the text, multi-line output renders correctly.
- **Worker plot capture (US-045 `runWithPlotParam`).** Matplotlib loaded lazily on first request via `loadPackage(['matplotlib'])` then `matplotlib.use('AGG')` (no display server in worker). Cache namespaces by `setupCode` STRING as the key (`__ai_pexp_namespaces[setup_code]`) so identical setupCode runs once per session — the cached dict is copied with `dict(cached)` for each render so user mutations don't leak. Capture the most-recent figure with `plt.figure(plt.get_fignums()[-1]).savefig(buf, format='png', bbox_inches='tight', dpi=110)` then `plt.close('all')` before the next render. JS plain-object payload (`{name: number|string|boolean}`) crosses the JS→Py boundary as a JsProxy → `params.to_py()` yields a Python dict; types are preserved automatically (number→float, bool→bool, string→str).
- **Next dev (Turbopack) can hang under back-to-back playwright runs.** Symptom: first navigation succeeds, second test run's `page.goto` times out and `curl` to ANY route hangs indefinitely. Recovery: `pkill -f "next dev"` and restart on a different port. Suspect dangling chromium HMR socket from the previous run.
- **react-hooks/set-state-in-effect rule.** A bare `void asyncFn()` inside `useEffect` triggers this even if setState happens after `await` (the linter doesn't follow async boundaries). Gate the call behind a one-shot `useRef(false)` flag (`if (initialRenderRef.current) return; initialRenderRef.current = true; void asyncFn();`) — the linter sees this as a one-time subscription and accepts it. Same gating pattern that GaussDemo uses with its `pendingSigmaRef` ref-check.
- **Mark a non-Code section "done".** PATCH `/api/progress` with `{ courseSlug, lessonSlug, sectionState: { [sectionId]: { done: true } } }`. `applyProgressPatch` shallow-merges into `sectionState[sectionId]`, so sibling fields on other sections are untouched. Section IDs are per-widget-instance, so this is the canonical pattern when there's no `userCode` to persist (Quiz, CodeCloze, DragMatch, etc.).
- **Mixing CSS shorthand `border` with separate `borderColor` re-renders trigger a React style warning.** Don't compose `{ border: '1px solid X' }` with a hover override `{ borderColor: 'Y' }`. Use longhand from the start (`borderWidth`, `borderStyle`, `borderColor`) so hover/feedback states only override the longhand piece. Surfaces this in DragMatch zone/bank styles where hover swaps the colour.
- **dnd-kit (`@dnd-kit/core` + `@dnd-kit/sortable`) is already in `package.json` (added pre-MVP).** `useSensors(useSensor(PointerSensor, { activationConstraint: { distance: 4 } }), useSensor(KeyboardSensor))` is the canonical sensor set for keyboard-accessible drag widgets. `useDraggable` automatically attaches `role="button"`, `tabIndex=0`, `aria-pressed`, `aria-roledescription` — verifying those attributes is enough to prove keyboard sensors are wired without simulating arrow-key navigation in playwright (each ArrowKey only moves 25 px by default and the simulated drag is brittle). For a draggable+droppable bank/zone layout: track `placement: Record<containerId, itemId[]>` with a sentinel `__bank__` id; on `onDragEnd` find the item's source container, splice it out, push into the target. Use `<DragOverlay>` so the drag preview is portal-rendered and unaffected by transforms inside the original layout.
- **Inline syntax-highlight for cloze-style widgets.** Don't pull in CodeMirror with `Decoration.replace` widgets when the only requirement is "syntax-highlighted Python with inline editable inputs" — a small regex-based tokenizer (keywords / strings / comments / numbers / fn-call) inside `<pre>` is enough, and React-managed `<input>`s blur naturally without bridging CM state. CodeCloze's `tokenizePython` is the reference implementation. Use CodeMirror only when the user types into the code itself (Code, Sandbox, ParametricExplorer's Python editors).
- **Status badge selector for browser tests.** `[data-section-id="<id>"] [data-status="done"]` (NOT `data-widget-status`). `StatusBadge` in `src/widgets/Widget.tsx` exposes the value via `data-status`.
- **`type ComponentType` import for `widgetRegistry[type].component`.** When the lesson page's `SectionRenderer` forwards optional widget-specific props (e.g. `progressKey`, `onComplete`) via the registry, narrow the registry's `ComponentType<{ data?: unknown }>` with a local cast: `widgetRegistry.codeCloze.component as ComponentType<{ data?: unknown; progressKey?: typeof progressKey; onComplete?: () => void }>`. Add `type ComponentType` to the existing `from 'react'` import block in `page.tsx`.
- **Avoid `useEffect`+`setState` for "clamp paging index when filter shrinks rows".** The `react-hooks/set-state-in-effect` rule rejects `useEffect(() => setPage(Math.max(0, totalPages-1)))`. Instead, derive a `clampedPage = Math.min(page, totalPages-1)` value during render and use it for slicing/indicator/disabled-state — let `setPage` only flip on actual user click. This keeps the linter happy and removes a redundant render cycle when filters narrow the result set.
- **Sticky thead inside an `overflow:auto` scroll container.** `position: sticky; top: 0; z-index: 1` on `<thead>` plus a non-transparent `background` on each `<th>` (or on the `<thead>` itself) is enough — no JS needed. Wrap the `<table>` in a `div` with `maxHeight: '60vh'; overflow: auto` so the sticky context is the wrapper rather than the page.
- **Cross-origin iframe postMessage spying is blocked.** Playwright (Chromium) throws `SecurityError: Blocked a frame with origin "..." from accessing a cross-origin frame` if you try to replace methods on `iframe.contentWindow` for a third-party embed (YouTube, Vimeo, etc.). For seek/play verification on cross-origin video embeds, prefer (a) observable side-effects in the parent's DOM/state (e.g. our own `data-active` flips), or (b) routing the test through an HTML5 `<video>` MP4 path where `video.currentTime` IS reachable from the parent and `Object.defineProperty(v, 'currentTime', { get, set, configurable: true })` works. Also: install the descriptor override AFTER reading the post-mount value, otherwise the React `useEffect` initial assignment is lost.
- **Adding a new media type to course assets** = extend `CONTENT_TYPES` in `src/app/api/courses/[slug]/assets/[...path]/route.ts` (one map gates both the GET Content-Type header and the PUT extension allow-list). Currently supports `.png/.jpg/.jpeg/.svg/.webp/.gif/.mp4/.webm`.
