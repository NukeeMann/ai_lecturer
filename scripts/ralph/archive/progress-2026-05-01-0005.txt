## Codebase Patterns
- Repo dir is named `US-001` (capitalized) → cannot run `create-next-app .` directly because npm rejects capital letters in package names. Workaround: scaffold into a temp dir (e.g. `/tmp/ai-lecturer-scaffold`), then copy files into the worktree (skip the inner `.git`), and set the package name in `package.json` manually.
- `shadcn@latest` (v4.x) emits Tailwind v4 / `base-nova` style by default — incompatible with a Tailwind v3 project. Use `shadcn@2.3.0` for v3-compatible init, or write `components.json` by hand.
- Tailwind v3 baseline = `@tailwind base; @tailwind components; @tailwind utilities;` in `globals.css` + `tailwind.config.ts` with `content: ["./src/**/*.{ts,tsx,js,jsx,mdx}"]` + `postcss.config.js` with `tailwindcss` and `autoprefixer` plugins. Theme/token wiring belongs in US-002, not US-001.
- Design tokens live in `src/styles/tokens.css` (canonical source from `claude/design/source/tokens.css`) and are imported at the top of `src/app/globals.css`. Tailwind utilities resolve through CSS vars, so changing a `--*` value at runtime updates Tailwind classes too.
- Theme/accent/density are switched by `data-theme` / `data-accent` / `data-density` attributes on `<html>` (defaults: `light` / `default` / `comfortable`). Selectors in tokens.css are scoped to `:root[data-theme=…]` etc. — adding new variants means adding a new `:root[data-…="…"]` block, not a new file.
- Geist Sans + Mono are loaded via `next/font` (`geist/font/sans`, `geist/font/mono`) in `src/app/layout.tsx`. Their `.variable` classNames define `--font-geist-sans` / `--font-geist-mono`; tokens.css references those via `var(--font-geist-sans)` inside `--font-sans` / `--font-prose` / `--font-display`. Don't hardcode font names anywhere else.

- **Zod is pinned to v3** (`^3.25.x`) because `zod-to-json-schema` returns an empty object on Zod v4. Don't bump zod to v4 unless the `zod-to-json-schema` import also changes. (Zod v4 has a native `z.toJSONSchema()`, but our AC mandates the third-party lib.)
- **Vitest needs its own alias config.** `vitest.config.ts` must declare `resolve.alias = { '@': fileURLToPath(new URL('./src', import.meta.url)) }`. Vitest does NOT read `tsconfig.json#paths`. Next + `tsc` + `tsx` (used by `npm run build:schemas`) DO auto-pick it up.
- **Eslint config does not exempt `_`-prefixed unused vars.** For "drop one field" test fixtures, use `const broken: Partial<typeof obj> = { ...obj }; delete broken.field;` — destructuring with `_name` triggers `@typescript-eslint/no-unused-vars` warnings.

Adding a new widget = new folder under `src/widgets/<Name>/` + register a variant in `src/lib/schemas/lesson.ts` + add it to the `widgets` map in `src/widgets/schemas/build.ts`. `npm run build:schemas` regenerates the committed `*.json` files in `src/widgets/schemas/`.
- **Filesystem helpers** live in `src/lib/server/` (server-only — never import from a `'use client'` module). `paths.ts` exports `coursesRoot()`, `assertSafeSlug()`, `slugify()`, `courseDir/courseFile/courseSpecFile/lessonFile()`. `atomic.ts` exports `atomicWriteJson(path, data)` (writes to `<path>.tmp` then `fs.rename`). `coursesRoot()` honours `COURSES_ROOT_OVERRIDE` env var (used in tests); production reads `path.join(process.cwd(), 'courses')`. - **Next 16 route handlers + vitest.** Tests can import handlers directly from `src/app/api/.../route.ts` and call them with a synthesised `Request` and `{ params: Promise.resolve({...}) }` (Next 15+ wraps params in a Promise). `NextResponse.json()` returns a real `Response`, so `await res.json()` and `res.status` work in tests. Put the test file OUTSIDE `src/app/` (e.g. `src/lib/server/api.test.ts`) so Next doesn't try to compile it as a route — vitest's `include: 'src/**/*.test.ts'` still picks it up.
- **Slug rules.** `assertSafeSlug` rejects empty strings and any slug containing `/`, `\`, or `..` (path-traversal protection). Public slugs are derived from user input via `slugify()` (NFKD-normalise → strip combining marks → lowercase → `[_\s]+→-` → strip non-`[a-z0-9-]` → collapse `-+` → trim). Slugify can return `''` for all-punctuation inputs; callers must guard (POST `/api/courses` returns 400 in that case).
- **Pyodide worker singleton.** Web Workers are bundled by Turbopack via `new Worker(new URL('./worker.ts', import.meta.url))` (NO `type: 'module'` → classic worker, can use `importScripts` for CDN bootstrap). The worker file at `src/lib/pyodide/worker.ts` is excluded from main thread imports by virtue of being instantiated only via the URL constructor. Client hook lives at `src/lib/pyodide/client.ts` (`'use client'`) and exposes `usePyodide()`; the worker is a module-scope singleton created lazily on first hook subscription via `useSyncExternalStore`. Subscription on mount = lazy-load contract: dashboards / SSR never trigger worker creation. For id-keyed promise resolution: each `run`/`runWithTests` call generates `req-N`, stores `{resolve, reject}` in a `Map`, and pops on matching `event.data.id`. Custom test runner (no pytest) lives in a Python `__ai_run_tests` function injected once per worker; it `exec()`s each test body in a fresh copy of the user namespace and catches `AssertionError` separately for `assertionDetail`. Test results array shape: `[{name, passed, traceback?, assertionDetail?}]`.
- **CodeMirror 6 setup.** Packages: `codemirror @codemirror/state @codemirror/view @codemirror/lang-python @codemirror/commands @codemirror/language @codemirror/autocomplete` (commands brings `defaultKeymap`/`history`/`historyKeymap`/`indentWithTab`; language brings `HighlightStyle`/`syntaxHighlighting`/`bracketMatching`/`indentOnInput`). Theme via `EditorView.theme({...})` consuming our `--code-bg/--code-text/--code-keyword/...` CSS vars. Highlight via `HighlightStyle.define([{ tag: t.keyword, color: 'var(--code-keyword)' }, ...])` from `@lezer/highlight` tags. Editor instantiated once in `useEffect(() => {...}, [])` with `EditorState.create({doc, extensions:[…]})`; subsequent doc updates flow via `view.dispatch({changes:{from,to,insert}})`, NOT by re-rendering. Use `EditorView.updateListener.of((u)=>u.docChanged && setCode(u.state.doc.toString()))` to mirror doc into React state.
- **eslint react-hooks/refs rule is strict.** Never write `someRef.current = value` at component top level — must be inside `useEffect(() => { someRef.current = value; }, [value])` or inside an event handler. Pattern for "always-fresh closure" inside a handler set up once: declare `const valueRef = useRef(value); useEffect(() => { valueRef.current = value; }, [value]);` then read `valueRef.current` inside the long-lived closure.
- **Cmd/Ctrl+Enter in CodeMirror.** Use `keymap.of([{ key: 'Mod-Enter', preventDefault: true, run: () => { ...; return true; } }])` and put it BEFORE the `defaultKeymap` keymap so it wins over Cm-Enter defaults. `Mod` resolves to ⌘ on Mac and Ctrl elsewhere. Have the `run` callback dispatch via a ref (`handleRunRef.current()`) so it always picks up the latest closure.
- **Progress PATCH for sectionState.** PATCH `/api/progress` with body `{ courseSlug, lessonSlug, sectionState: { [sectionId]: { userCode } } }`. To CLEAR a section's state (e.g. on Reset), send `{ [sectionId]: {} }` — the server's `applyProgressPatch` shallow-merges into existing `sectionState[sectionId]` then replaces it, so `{}` overwrites and effectively wipes the entry's userCode. Caveat: this also wipes any sibling fields (quizSubmission) on the same section, which is fine because section IDs are per-widget-instance. To mark a section "done", PATCH `{ userCode, done: true }` together — `done?: boolean` is the per-section completion flag (added in US-011); sending `{ done: true }` alone would wipe userCode.
- **CodeRunner slots (US-011).** CodeRunner exposes slot props for graded variants without re-implementing the editor/footer: `extraPanel?: ReactNode` (rendered between output panel and footer), `primaryAction?: { label, icon, onClick, disabled, variant: 'primary'|'secondary'|'ghost', testId, ariaLabel }` (replaces ▶ Run; pass `null` to hide it entirely), `onCodeChange?: (code) => void` (mirror doc into parent state), `onReset?: () => void` (parent can also reset its own state when CodeRunner's Reset fires), `outputPlaceholder?: string`. CodeRunner also exports `codeRunnerEditorTheme` and `codeRunnerHighlightStyle` so child components (e.g. inline read-only test bodies) match the editor's look. Read-only CodeMirror needs BOTH `EditorState.readOnly.of(true)` and `EditorView.editable.of(false)`.
- **TS target ES2017.** The regex `s` (dotAll) flag triggers `TS1501`. Use `[\s\S]` in patterns that need to span newlines, never `/.../s`.
- **Lesson navigation.** Flat ordered lesson list = `course.modules.flatMap(m => m.lessons)`. Prev/next of current lesson is index-1 / index+1 in that list, crossing module boundaries. Client navigation uses `router.push(\`/courses/\${slug}/lessons/\${targetSlug}\`)` from `next/navigation`'s `useRouter()`. Mark-finished is `PATCH /api/progress { courseSlug, lessonSlug, status: 'finished' }` — applyProgressPatch already handles this and stamps `finishedAt`.

- **Learnings for future iterations:**
  - **Keyboard-shortcut hook surface.** `useKeyboardShortcuts(shortcuts: KeyboardShortcut[])` is the single funnel for any future global/page-scoped shortcuts. Each shortcut declares its own `match(e)` predicate, which lets callers decide whether to allow modifiers, what `e.code` vs `e.key` to use, and which target types to exempt. The hook has no opinion on key syntax (no parser), keeping it tiny. The hook also reads from a ref every keypress, so consumers don't have to memoise their array — important when handlers close over rapidly-changing React state (e.g. `progress`).
  - **`e.code` vs `e.key` for Space.** `e.key === ' '` works on US layouts but `e.code === 'Space'` is the layout-independent form and is what we use. For letters (`j`, `k`, `n`, `p`, `f`) we use `e.key` because that respects the user's layout.
  - **Buttons swallow Space by default.** `<button>` elements activate on Space, so a window-level Space handler must skip when `e.target instanceof HTMLButtonElement`/`HTMLAnchorElement` — otherwise the user can no longer fire focused buttons. Same exemption is not needed for j/k because letters don't activate buttons. The `isEditableTarget` check inside the hook intentionally does NOT include `<button>` because we want shortcuts to still fire when a button is focused (e.g. after clicking Mark complete).
  - **Scroll detection.** Section nav uses `getBoundingClientRect().top - mainRect.top + main.scrollTop` to compute each section's offset within `main`'s scroll content. Then for "next" we find the FIRST offset strictly past `scrollTop + buffer`, not "currentIdx + 1". The "first past viewport top" formulation is robust to settled-but-imperfect scroll positions (smooth scroll often lands ±a few px from target), whereas a `currentIdx + 1` lookup can return the same section after a smooth scroll lands slightly short.
  - **Scroll container is `main`, not `window`.** The lesson shell's main content lives inside a CSS grid cell with `overflow: auto`, so `window.scrollY` never changes inside the lesson view. Always operate on `[data-testid="lesson-content"]` (`.scrollTop` / `.scrollTo`) when adding scroll-aware lesson features.
  - **Reduced-motion.** Use the `preferredScrollBehavior()` helper for any keyboard-triggered scroll. Don't pass `behavior: 'smooth'` literally, and don't gate behind a state — `matchMedia` on each call is cheap and always reflects the latest user preference (e.g. if the user toggles the OS setting mid-session).
  - **PATCH /api/progress shallow-merges sectionState entries.** When marking a section done via Space, you MUST send the existing entry merged with `done: true` (not just `{ done: true }`), because the server replaces the whole `sectionState[id]` object with whatever the patch contains. The optimistic local state update needs the same merge to stay consistent.
  - **Global modal mounting.** `<GlobalShortcutsHost />` lives in `src/app/layout.tsx` so the `?` shortcut and modal work on every screen (dashboard + lesson). For other in-app affordances to open the modal without prop-drilling, dispatch `new Event('shortcuts:open')` on `window` (or call the exported `openShortcutsModal()` helper). This pattern is reusable for any future global UI surface.
  - **`focusModeRef` mutation site.** The eslint `react-hooks/refs` rule allows `someRef.current = value` ONLY inside event handlers / `useCallback` / `useEffect`. The focus-mode toggle mutates the ref inside its `useCallback` body — that's the safe location. Mutating refs at component top level is still a hard no.
  - **Fixture course cleanup.** Browser tests for keyboard nav need a multi-section lesson + a sibling lesson for `n`/`p`. Fixture lived at `courses/us021-fixture/` (with `PROGRESS_FILE_OVERRIDE=/tmp/us021-progress.json`); deleted before commit. `courses/` is still NOT gitignored.

Blur or Enter commits (calls `onChange(trimmed)` if non-empty and changed); Escape cancels. The setState-from-effect lint rule (`react-hooks/set-state-in-effect`) was the trickiest piece — refactored to do `requestAnimationFrame(() => inputRef.current?.focus())` inside the effect (no setState there) and have the click handler call `setDraft(value)` directly. Same pattern in `<MinutesEdit>` for the per-lesson estimated-minutes pill.
- **Module-card click-to-select vs click-to-rename.** AC says BOTH "each card click selects" AND "click title to edit" — same gesture, two actions. Resolution: card click anywhere selects; clicking the title only enters edit mode IF the module is already selected. Implemented via an `editEnabled?: boolean` prop on `<InlineEdit>` — when false, the click handler doesn't `stopPropagation()` and doesn't enter edit, so the click bubbles up to the parent card's `onClick` (which selects). Module cards pass `editEnabled={selected}`. Lesson rows in column 3 don't have a "selected" notion, so they always pass the default `editEnabled=true`. Course title/description always editable (no parent selection model). Test impact: clicking a not-yet-selected module via `.click()` in the title region selects but doesn't enter rename, which matches the user's expected first-touch behavior.
- **Drag-and-drop with @dnd-kit.** Installed `@dnd-kit/core@^6.3.1`, `@dnd-kit/sortable@^10.0.0`, `@dnd-kit/utilities@^3.2.2`. Single `DndContextWrapper` component wraps both module and lesson lists — same `<DndContext>` + `<SortableContext>` + `verticalListSortingStrategy` config, accepts an `ids: string[]` and `onReorder(fromId, toId)` callback. Sortable items use `useSortable({ id })`. Sensors: `PointerSensor` with `activationConstraint: { distance: 4 }` (so ≤4px movement is still treated as a click — important because the grip handle is also clickable for the test/user) and `KeyboardSensor` with `sortableKeyboardCoordinates` (free a11y). Reorder applies `arrayMove(modules, from, to)` from `@dnd-kit/sortable`. The grip is a separate small `<button>` with `{...attributes} {...listeners}` — only the grip drags, the rest of the card is clickable normally.

Clicking that confirms and calls `onConfirm()`. Clicking elsewhere on the document cancels (via `mousedown` listener installed only while armed). Trash button is `disabled` when only one module/lesson would remain, so the user can't fully empty a parent. The two testid prefixes are `stage3-{module|lesson}-trash-{id}` (initial) and `stage3-{module|lesson}-trash-confirm-{id}` (confirm) — the second has the first as a prefix, so any `[data-testid^="stage3-module-trash-"]` selector will match both. Tests use exact `[data-testid="..."]` strings.

- **Learnings for future iterations:**
  - **`@dnd-kit/sortable` setup primer.** Three packages: `@dnd-kit/core` (DndContext, sensors), `@dnd-kit/sortable` (SortableContext, useSortable, arrayMove, sortableKeyboardCoordinates, verticalListSortingStrategy), `@dnd-kit/utilities` (CSS.Transform.toString helper). Top-level wrapping is `<DndContext><SortableContext items={ids} strategy={verticalListSortingStrategy}>{children}</SortableContext></DndContext>`. Each sortable item calls `useSortable({ id })` and applies `style={{transform:CSS.Transform.toString(transform), transition}}`, plus `{...attributes} {...listeners}` to the drag handle (NOT the whole card — that would prevent normal click). Sensors must be created with `useSensors(useSensor(PointerSensor, ...), useSensor(KeyboardSensor, ...))` to support both mouse/touch and a11y. The `activationConstraint: { distance: 4 }` on PointerSensor is essential when the drag handle is also clickable — without it any click on the handle starts a drag.
  - **`react-hooks/set-state-in-effect` workaround for "sync local state on toggle".** Common pattern is `useState(false)` for editing + `useEffect(() => { if (editing) setDraft(value); ... }, [editing, value])`. The lint rule rejects this. Workaround: collapse "editing flag" + "draft string" into one `useState<string | null>(null)` where null means "not editing" and any string means "editing this draft". Setting up edit state happens in the click handler (not an effect); the effect only runs `requestAnimationFrame(() => inputRef.current?.focus())`. This pattern applies to any "edit-on-click" component where the input value should snapshot the prop at edit-start.
  - **Click-to-select vs click-to-rename conflict.** When a card is both a "selectable item" and an "inline-renameable text" surface, single-click on the title is ambiguous. The pattern that worked here: `editEnabled={selected}` on the InlineEdit. First click selects (via card-onClick bubble); subsequent click on the title (now-selected) enters rename. The handler in InlineEdit MUST `if (!editEnabled) return;` BEFORE `e.stopPropagation()` — otherwise the click is swallowed and the card never receives select. For other surfaces (course card in column 1, lesson rows in column 3) there's no parent selection model so always-on edit works.
  - **Inline-confirm pattern (delete with no modal).** `<DeleteButton>`: `armed: boolean`, click → arm, swap UI for a red "Delete?" button, click again → confirm. Auto-cancel on outside click via `document.addEventListener('mousedown', ...)` mounted while armed. Stop propagation on both initial-trash and confirm clicks so the parent card doesn't also receive the click. Disabled when removing the item would empty the parent (e.g. last module / last lesson) — friendlier than letting the click through to a no-op.
  - **Wizard draft persistence across Back/Forward.** The mount-effect `if (!draft.structure) setDraft(...)` only fires when `draft.structure === null`. Going Back → Stage 2 keeps `draft.structure` non-null in the parent's useState. Re-entering Stage 3 finds it non-null and skips re-seeding. Same pattern would apply to any future stage that wants "first-entry seed, then preserve user edits."
  - **selectedModuleId synchronization without an effect.** Naive approach: `useEffect` watches the modules array and calls `setSelectedModuleId(modules[0].id)` when the user-selected id is missing. The set-state-in-effect lint rule rejects that. Cleaner: keep `selectedModuleId` as the user's explicit pick, then derive `effectiveSelectedId` via `useMemo` — falls through to `modules[0].id` when the user pick is null/missing. UI uses `effectiveSelectedId` for highlight + which column-3 list to show. The actual `selectedModuleId` only changes on click, so no effect needed.
  - **Playwright drag-and-drop with @dnd-kit.** The grip handle has its own `data-testid`. Test pattern: `mouse.move(fromX, fromY); mouse.down(); mouse.move(fromX+6, fromY+6, {steps:5});` (satisfy the 4px activation distance via small jitter) `mouse.move(toX, toY, {steps:12}); mouse.up();`. The two-stage move is critical — going straight to target sometimes fails to trigger drag in headless. The `{steps}` option is what makes @dnd-kit see continuous pointermove events.
  - **Wizard state lift point.** Per US-024 learning: simple useState in parent works. For US-025, the structure mutators (setCourseTitle, addModule, removeLesson, etc.) are all defined in `Stage3Cascade.tsx` and operate on the draft via `setDraft` passed from the parent. Stage4Preview reads `draft.structure` for display. No context needed yet. If a future stage needs deeply-nested children to mutate the structure, that's the time to add a context wrapper.
  - **lucide-react icons used in cascade.** `GripVertical`, `Plus`, `Trash2` (already used elsewhere), `ArrowLeft`, `Sparkles` (for the primary "Looks good — generate" CTA). All present in `lucide-react@^1.14.0` — no new icon library needed.
  - **No new fixture courses needed.** This story doesn't touch lessons, progress, or the courses dir — entirely client-side wizard state. No `PROGRESS_FILE_OVERRIDE` and no `courses/` writes during browser tests, so no cleanup risk. Other UI stories that DO write fixtures should still follow the established cleanup pattern.
